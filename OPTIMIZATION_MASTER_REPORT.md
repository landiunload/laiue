# Сводный отчёт по оптимизациям движка

Состояние: исходный интеграционный кандидат на базе `wip/providers-2026-09-23` и `codex/architecture-tradeoffs` уже вошёл в `main`; обе ветки Dependabot также учтены в его истории. Ниже сохранена исходная оценка, а в конце добавлено измерение последующей оптимизации стриминга.

## Что вошло в кандидат

- Перенос модулей и provider-интерфейсов из `wip/providers-2026-09-23`.
- Оптимизации раундов 1–2 по world/physics, audio, render, content, media, numeric, modding и task pool; вместе с ними — регрессионные тесты и ручные A/B-бенчмарки.
- Раунд 3: хранение backend в заголовке объекта рендера, компактный порядок загрузки модов и однопроходное перечисление контент-каталога через компактный staging-буфер.
- Ветка Dependabot `actions/checkout` объединена; в актуальном workflow уже используется тот же SHA `3d3c42e5…` для v7.0.1.
- Ветка Dependabot `actions/download-artifact` объединена в истории. Её workflow основан на устаревшей структуре CI; актуальный workflow не скачивает artifacts, поэтому SHA v8.0.1 там пока негде использовать. Старые jobs из этой ветки не возвращались.

## Интеграция и исправления

- Git обнаружил девять содержательных конфликтов. В разрешении сохранены provider-границы `wip`: аудиомодуль получает контент только через таблицу сервиса, renderer оставляет provider-файлы и переносит `renderer_internal.h` в новое расположение, world batch освобождает память через allocator самого мира.
- Переписаны устаревшие пути к исходникам в CMake после переезда `src/render`, `src/physics` и `src/media`.
- DDA- и UI-тесты подключены к новым публичным интерфейсам. Тест звукового PCM16 обращается к загрузчику через таблицу сервиса; тесты world, panorama и texture pack явно устанавливают необходимые providers.
- Исправлена проверка optional graphics module: headless-тест теперь выбирает offscreen Vulkan, а не оконный D3D12 через AUTO.
- При слиянии веток Dependabot сохранён актуальный workflow из интегрируемой архитектурной ветки, а не возвращены старые jobs упаковки, которые расходятся с новым набором CMake presets. Используемый checkout SHA уже совпадал с версией v7.0.1 из Dependabot; `download-artifact` в актуальном workflow не вызывается.

## Решение перед публикацией

Оптимизацию мира оставил: после восстановления корректной работы benchmark provider setup замедление одиночной записи не подтвердилось, а повторные измерения показали ускорение одиночного сценария примерно на 66.5% и пакетных сценариев на 94.0–97.4%. Компактный каталог тоже оставлен: он уменьшает пик памяти примерно на 29% и сокращает общее время набора сценариев в 8 из 9 пар; цена — лишь 8–27 мкс на перечислении очень маленького каталога из 64 файлов. Release/Debug CTest кандидата прошли 71/71.

## Последующее измерение: очередь стриминга чанков

- `QueueChunkIfMissing` теперь объединяет поиск и вставку в один проход открытой адресации. Если запись уже есть, она возвращается; если ключа нет, первый пустой слот сразу заполняется. Раньше сначала выполнялся `FindEntry`, а затем отдельный `InsertEntry`, то есть отсутствующий чанк проходил цепочку пробирования дважды.
- A/B сравнение против `HEAD eebc212` выполнено на Windows x64/MSVC Release. Для каждого варианта запущено по три полных прохода standalone `laiue_streaming_benchmark`, радиус 12, 200 шагов; сравнивается медиана времени `SetCenter` на вызов.

| Сценарий | База, мкс/вызов | Изменение, мкс/вызов | Снижение времени |
|---|---:|---:|---:|
| worker sleep 0 мс | 83.599 | 73.399 | 12.2% |
| worker sleep 8 мс | 155.300 | 139.800 | 10.0% |

Это выигрыш именно в микробенчмарке смены центра, а не измерение FPS игры. Для этой правки расход памяти отдельно не замерялся; алгоритм не добавляет таблиц или постоянного состояния. Добавлен тест повторной установки того же центра: он проверяет, что заявки и эпоха центра не меняются; тест стриминга прошёл в Release и Debug.

Ревью не нашло других actionable-дефектов в библиотечном коде или остальных benchmark-изменениях.

### Кандидаты, которые не перенесены

- Увеличение lookahead rigid solver с 8 до 32 ухудшило медиану примерно на 0.36% для solver и на 0.74% для полного шага; production-константа оставлена прежней.
- Эксперименты с production chunk mesher не дали устойчивого выигрыша, поэтому изменён только harness.
- Alpha fast path в resampler из отдельной старой ветки дал в сумме сценариев лишь около 1.05% выигрыша, но замедлил zero-alpha сценарии на 7.1–7.6% и один sparse-alpha сценарий на 4.9%; он отклонён, поскольку результат заметно зависит от распределения альфы и памяти не экономит.

### Проверки интеграции

- Visual Studio 2026 / MSVC, CMake preset `windows-msvc`: полная Release-сборка и CTest **71/71**; полная Debug-сборка и CTest **71/71**.
- Отдельно собраны mesher, world batch, module host и оба rigid-body benchmark-targets. Module-host, world dense/sparse, mesher mixed и оба rigid-body benchmark smoke-запуска завершились с кодом 0.
- `git diff --check` прошёл. GitHub CI будет проверен после отправки коммита.

### Ragdoll: импульсы суставов без bigint-копий

Профиль callgrind шага 13-тельной ragdoll примера walk показал, что около **70%** инструкций уходило на `malloc`/`free` и временные `InfiniteCoord`. `VoxelRigidBodyAdd{Linear,Angular}Velocity` шли в int64-путь только при точной кратности дельты 2⁻³², которой у импульсов решателя почти не бывает, поэтому каждая ненулевая компонента собиралась через четыре временных bigint. Исправление:

- путь через `trunc(delta·2³²)` при попадании в int64 даёт то же целое, что и общий путь (масштабирование степенью двойки точно, разбиение на целую и дробную части точно, усечение распределяется по сумме одного знака);
- однолимбовые компоненты меняются на месте внутри physics, без трёх косвенных вызовов через таблицу numeric-сервиса; перенос, канонический ноль и погашение по-прежнему идут через владельца памяти;
- набор из трёх компонент остаётся атомарным: быстрый путь включается, только если ни одна компонента не может отказать;
- решатель суставов не переводит неизменный центр тела из bigint на каждой оси.

Новый `laiue_ragdoll_benchmark` (ходьба квадратом при 128 Гц, медиана 7×1024 тиков), Linux GCC 13 Release x86-64-v3, пять чередующихся пар baseline/candidate:

| Сценарий | Baseline | Candidate | Изменение |
|---|---:|---:|---:|
| 13-тельная ragdoll, контроллер walk | 409.6 мкс/тик | **77.7 мкс/тик** | **−81% (×5.3)** |

Checksum конечного состояния совпал во всех прогонах. `laiue_physics_benchmark` (три чередующиеся пары): плотные сцены −1…−5%, свободное падение и опора в пределах шума ±4% (тот же разброс у не затронутого `rigid.rebase`); все `final_state_hash` совпали. Тест `laiue.physics.velocity_add` сверяет быстрый путь с bigint-эталоном на переносе лимба, точном погашении, нуле, многолимбовых значениях, дельтах меньше 2⁻³² и вне int64; две внесённые вручную мутации он ловит.

### Инструменты, оставленные в репозитории

- Санитайзерный профиль делает UB фатальным (`-fno-sanitize-recover`) и включает `float-cast-overflow`, которого GCC нет в `-fsanitize=undefined`.
- `LAIUE_BUILD_FUZZERS` и preset `linux-clang-fuzz`: фаззеры картинок, звука, zlib и манифестов модов/модулей; CTest и новый CI job повторяют корпус `tests/fuzz/corpus`, где лежат и входы, ронявшие декодеры.
- CI Vulkan job ставит `libx11-dev`, поэтому X11-окно и ввод снова собираются и проверяются.

### Проверено без находок

- libFuzzer, 10–15 минут на цель: манифесты модов ~48 млн и модулей ~28 млн прогонов, inflate ~13 млн, картинки ~0.7 млн, звук после исправлений ~0.17 млн.

### Рассмотрено и отклонено

- Половинная окрестность в хеш-сетке broadphase: пару сейчас перечисляет тело с меньшим `stableOrder`, и смена владельца пары изменила бы порядок контактов и детерминированный результат.
- Хранение одного лимба внутри `InfiniteCoord` без кучи: поле `limbs` — часть публичного ABI, его читают потребители; изменение требует новой версии API.
- `-fno-asynchronous-unwind-tables` ради размера: исключение C++-обратного вызова приложения перестало бы проходить сквозь кадры движка.

### Потоковый звук: явный выбор памяти против CPU

Быстрый путь готовых PCM-клипов сохранён. Потоковый режим включается
новыми API явно; он читает и декодирует вне output callback. Фиксированное
кольцо: 8192 кадров. Собственный heap callback-источника: WAV 49 632 байта,
MP3 116 856 байт независимо от длительности; файловый адаптер добавляет

Это не RSS: не учтены память пользовательского источника, общая память
устройства/backend, накладные расходы allocator и резерв native worker
stack. Системный поток использует один worker на stream.

| Stereo, медиана | 604 | 12091 | +1901,8% |

Checksum PCM/stream совпал: `10604107594001403779`.

Относительные проценты велики, потому что исходный PCM-путь очень дешёвый.
Абсолютно stream стоил 0,924/1,209 мкс на буфер 256 кадров против
0,0479/0,0604 мкс PCM. Замер включает WAV decode + весь offscreen mix;
он не измеряет дисковый I/O, MP3 или scheduling системного worker.
Первый предварительный стенд показывал +1710%/+2041%; окончательные
значения выше получены сохранённым самостоятельным стендом. Поэтому
уменьшение памяти не навязывается существующим PCM-клиентам.

Точный MP3 seek восстанавливает историю декодера от начала, O(позиции);
это документированный компромисс ограниченной памяти и времени перемотки.
Пакетная SIMD-обработка streaming voice может стать следующей отдельной
оптимизацией; в текущий проверенный вариант она не включена.

### Надёжность, автономность и границы проверки

Независимое ревью закрыло ошибки освобождения stream при отказе queued
STOP, числовые переполнения расчёта prefetch и NaN speed. Освобождение
требует подтверждения consumer о завершении voice и fences команды/кадра.
Тесты покрывают полный ring, seek, pause, EOF, loop, очередь и worker.

Для графического адаптера проверяются копирование геометрии/UV,
материальные батчи, свет, статический кэш, frustum, rebase, большие
координаты, близкие ячейки при ограниченном бюджете, ошибки загрузки
и отказ heap allocation. Подстановка allocator существует только в
отдельном тестовом объекте, собранном из копии production source в build;
публичных fault injection hooks нет. Исправлено потерянное владение
успешно перемещённым массивом после отказа другой allocation,
signed overflow origin и статистика вытесненных ячеек в том же update.

Паки анимаций проверяют границы LE-кодека, иерархию, интерполяцию, skinning,
непересекающиеся буферы, malformed input и необязательное наличие content.
Это CPU-основа; отдельного выигрыша скорости skinning пока не заявлено.

Локально подтверждены итоговые MSVC Debug и Release по 92/92, clang-cl
Debug 91/91 до последних регрессий адаптера, узкие Debug/Release тесты новых модулей,
4000 запусков codec libFuzzer+ASan и полная Android CORE link closure
без LTO. Копия с восстановленной ошибкой порядка allocation падает на новой
регрессии; исправленный код проходит. Остальные платформы проверяет CI.
Warnings-as-errors распространяется на компилятор и линкер.

Первая CI-проверка macOS выявила прежнее дублирование статических архивов

## Раунд 29: этап 2 — общий игровой runtime, 2026-10-05

Desktop и Android используют один `WalkGameplay`: актёр, фиксированный шаг
128 Гц, ориентация, камера, ввод, правки мира и rebase. Оболочки владеют
окном/NativeActivity, часами, накопителем времени, UI и GPU-ресурсами.
Общие C-файлы компилируются один раз в частную библиотеку примера;
публичный ABI движка не менялся. Контракт — `docs/walk_gameplay.md`.

Глобальная привязка physics заменена контекстом экземпляра. Неверная
привязка, освобождение или отказ одной сессии не меняют другую. Проверки
callback учитывают фактический размер таблицы, объявленный `structSize`
и ABI до чтения хвоста. Partial creation с ненулевым output очищается;
Release выполняется до выгрузки host. Provider error останавливает игру,
не подменяет непрочитанный блок воздухом. Health проверяется также после
meshing и перед итоговым PASS. Ошибка отката rebase явно запрещает
Step/Edit/Rebase; owned тела с limb-указателями не копируются.

Принятый импульс прыжка расходуется один раз и переживает кадр без тика.
Held jump требует отпускания, старое удержание после паузы не повторяет
прыжок. Аналоговые оси сохраняют отклонение и ограничиваются кругом;
новый yaw действует в текущем тике, в том числе при вертикальном взгляде.
BREAK→PLACE внутри одного пакета видит промежуточную правку; foreign/stale
камера сохраняет ожидающий импульс. Огромные абсолютные координаты не
переводятся во float для измерения смещения.

Android game живёт независимо от Vulkan surface. Проверочный сценарий
подтвердил точное сохранение game tick/revision, yaw/pitch, вида/материала,
целых и дробных координат, provider origin после rotation и HOME/resume
в том же PID. Получены 12 кадров, девять ACK и восстановлены настройки.
Проверка кадров не является сертификатом анатомии или качества походки.
V1 fallback пока имеет int32 voxel Z; переход на V2 остаётся отдельной
задачей шестого этапа.

При работающем ragdoll больше не создаётся запасной character controller:
исключена одна heap allocation на 176 байт (MSVC x64 и NDK ARM64 sizeof).

размер одного состояния, не разница общего RSS со старой игрой. После
provider-frame rebase GPU-чанки сбрасываются вне цикла фиксированных
шагов, а mesher scratch сохраняется без free/reallocate. CPU-shadow и
геометрия остаются отдельными scoped counters; общий выигрыш VRAM/RSS
на этом этапе не заявляется.

humanoid-кода, не FPS и не стоимость всего нового frame pipeline. Сырые

## Раунд 30: этап 3 — indexed geometry и GPU instancing, 2026-10-06

D3D12 и Vulkan используют независимые GPU index buffers и native indexed
commands. Один IB обслуживает несколько VB и диапазонов; signed base vertex
проверяется без переполнения. Индексы не раскрываются в новые вершины внутри
submit. Поддержаны транзакционные partial uploads, уничтожение после записи
команд и переполнение очереди deferred ranges. Vulkan учитывает реальный
uniform alignment, storage-buffer range и предел сырых uint32 indices.
D3D12 shader учитывает отличие VertexID от base vertex; переключение
generic/voxel восстанавливает scene constants.

Optional V2 tail сообщает capabilities и принимает 32-байтовые placements.
Размер DrawItemV2 сохранён. Старые таблицы и короткие prefix проверяются до
доступа к context/callback. Контракт — `docs/graphics_geometry.md`.

Walk хранит четыре вершины на quad и общий topology IB на набор чанков.
Mock-сцена Q=27, M=6: requested geometry 3888 → 2736 B (−29,63%). Сбой
создания/загрузки сохраняет полный прежний набор, scratch переживает rebase.
Мир моделей разделяет VB/IB лишь для одинаковой модели в двух или более
pure-ячейках с одним экземпляром. Unique/mixed/multiple-instance cells остаются
запечёнными по материалу; поворот, nonuniform/negative scale или несовпадение
запечённого света сохраняют старый путь. Восемь разных моделей в одной ячейке
сохраняют один прежний batch.

Adapter submit группирует placements по модели/материалу. После отсечения
singleton идёт обычным indexed submit без instance ring. Adapter-owned CPU
scratch выделяется в update; GPU provider может создавать свои ресурсы при
первом использовании. Warm update читает одну revision на ячейку, без
повторного census моделей/нормалей. Provider failure возвращает 0 и сохраняет
cache для retry; уже записанные команды не откатываются.
