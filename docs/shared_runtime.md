# Общие модули для выпущенных программ

Проект, ещё не реализован. Задача: игры и программы на laiue, установленные
из разных магазинов, пользуются одними файлами модулей. На диске нет дублей,
файлы не перезаписываются на месте, всегда лежит только последняя версия, и
обновление не ломает уже выпущенные программы.

## На чём это держится уже сейчас

Программа связывается только с `laiue::bootstrap` и грузит модули по имени
(`LaiueModuleHostLoadNamedProfileV1`). Зависимость в ABI называет сервис и
минимальную версию, а не файл: хозяин принимает более новый совместимый
сервис (`LaiueModuleRequirementV1`, `queryService` с `minimumVersion` и
`minimumSize`). Новые поля добавляются только необязательными хвостами
таблиц, их наличие проверяется по `structSize`. Значит, один новый модуль
может обслуживать программы, собранные со старыми, — это и позволяет держать
одну версию вместо нескольких.

## Что позволяют платформы

| Платформа и магазин | Общая папка модулей | Как избежать дублей |
|---|---|---|
| Windows: Steam, свой установщик | можно: `%ProgramFiles%\laiue` | общая среда выполнения, ниже |
| Windows: Microsoft Store (MSIX) | установить чужие файлы пакет не может | MSIX хранит одинаковые файлы разных пакетов один раз, если модули побайтно совпадают |
| Linux: пакеты дистрибутива, Flatpak | можно: пакет `laiue-runtime` или расширение Flatpak | менеджер пакетов; OSTree у Flatpak сам убирает дубли |
| Linux: контейнер Steam Linux Runtime | библиотеки хоста в контейнере недоступны | модули внутри игры |
| Android, Google Play | нет: приложения изолированы друг от друга, правила Play запрещают загружать исполняемый код в обход Play, а библиотеки чужого приложения меняются с его обновлениями | модули внутри APK, без распаковки (`extractNativeLibs=false`), Play отдаёт только ABI устройства |
| iOS, macOS App Store | нельзя: песочница и проверка подписи библиотек | модули внутри пакета |

Общую папку честно можно сделать там, где программы ставятся без песочницы:
Windows вне Store и Linux. В остальных случаях дубли убирает сама система, если
модули одной версии побайтно одинаковы. Поэтому первое требование ко всему
остальному — воспроизводимая сборка.

## Устройство

### Линия и версия

Линия среды выполнения — поколение ABI: `laiue/1`. Внутри линии версия
растёт по semver, и каждая новая обязана обслуживать все программы, собранные
с прежними версиями той же линии:

- ни одна таблица сервиса, ни одно поле и ни одна версия сервиса не
  удаляются и не меняют смысла;
- новое добавляется хвостом таблицы или новой версией сервиса рядом со
  старой; модуль может публиковать обе;
- несовместимое изменение открывает линию `laiue/2`. Она лежит рядом, но это
  не дубль, а другой ABI, и старые программы её не видят.

### Раскладка

```text
<корень>/laiue/1/
    current                      одна строка: действующая версия, например 1.4.2
    versions/1.4.2/
        manifest                 версия, файлы, SHA-256 каждого, подпись
        laiue_window.dll
        laiue_graphics_d3d12.dll
        ...
```

Корень — `%ProgramFiles%` на Windows, `/usr/lib` или `/opt` на Linux. Писать
туда может только установщик среды; программы только читают.

### Обновление без перезаписи

1. Новая версия распаковывается в `versions/1.4.3.partial`.
2. Проверяются подпись `manifest` и хэши всех файлов.
3. Каталог атомарно переименовывается в `versions/1.4.3`.
4. `current` атомарно заменяется (`PlatformFileReplaceDurable`).
5. Прежняя версия удаляется, как только её не держит ни один процесс.
   Занятые DLL Windows не даёт удалить, тогда удаление повторяется при
   следующем запуске установщика.

Версия ниже действующей не ставится никогда. Ошибку в выпуске исправляет
следующая версия, а не откат. В устойчивом состоянии на диске ровно одна
версия; вторая живёт, только пока её дорабатывает уже запущенная программа.

### Загрузка

`LaiueModuleNamedProfileV1` получает режим источника в зарезервированных полях:

| Режим | Поведение |
|---|---|
| `LOCAL` (по умолчанию) | как сейчас: модули рядом с программой |
| `SHARED` | только общая среда; без неё программа сообщает, что нужна среда, и как её поставить |
| `SHARED_THEN_LOCAL` | общая среда, а при её отсутствии, старой версии или неверной подписи — свои копии |

Программа знает минимальную версию линии, с которой собрана. Загрузчик читает
`current`, сверяет версию, проверяет подпись `manifest` вшитым открытым
ключом (Ed25519) и SHA-256 каждого загружаемого модуля. SHA-256 в движке уже
есть (кэш конвейеров), а набор модулей Windows весит около 0,5 МБ: проверка
добавляет к запуску порядка миллисекунды. Неподписанное из общей папки не загружается никогда.
Сборки, выпущенные до этого, работают как раньше: режим по умолчанию — `LOCAL`.

### Проверка совместимости в CI

«Только последняя версия» безопасна, пока её проверяют. CI хранит программы,
собранные с прошлыми выпусками линии: viewer, демонстрации, smoke-тесты игр.
Каждая новая версия модулей запускается под ними. Если хоть одна старая
программа ломается, выпуск не проходит.

## Что выпускать в каждом магазине

- **Steam, свой установщик на Windows:** `SHARED_THEN_LOCAL` или `SHARED` и
  установщик среды как зависимость (в Steam — через `installscript.vdf`).
- **Microsoft Store:** `LOCAL`. Модули воспроизводимы, и одинаковые файлы
  разных пакетов MSIX хранит один раз.
- **Linux:** расширение Flatpak `dev.laiue.Runtime` или пакет дистрибутива;
  в Steam Runtime — `LOCAL`.
- **Android, iOS, macOS:** `LOCAL`, как требует платформа. Размер уже сведён
  к минимуму: библиотеки очищены, не сжаты и выровнены, Play раздаёт по ABI.

## Цена и польза

Набор модулей сейчас занимает около 0,5 МБ на Windows и около 1,6 МБ на одно
ABI Android: общая папка экономит примерно столько же на каждой следующей
программе. Скорости она не добавляет. Главная польза — одно обновление
исправляет все программы сразу и уменьшает загрузки, когда появятся тяжёлые
модули. Главный риск — одна плохая версия ломает все программы сразу; его
закрывает проверка совместимости в CI.

## Этапы

1. Воспроизводимые сборки модулей и формат `manifest` с подписью и
   инструментом подписи.
2. Режимы источника в загрузчике и проверка подписи; по умолчанию `LOCAL`.
3. Установщик и обновлятель среды для Windows и Linux, проверка
   совместимости в CI.
4. Упаковка под магазины.

## Открытые решения

- Корень на Windows: на всю машину (`%ProgramFiles%`, один запрос UAC) или на
  пользователя (`%LOCALAPPDATA%`, без прав администратора, но копия у каждого
  пользователя Windows).
- Кто хранит закрытый ключ подписи среды.
- Когда открывать линию `laiue/1`: до версии 1.0 ABI ещё меняется (см.
  [CHANGELOG](../CHANGELOG.md)), поэтому раньше 1.0 линия будет обновляться
  чаще.
