# Общий игровой runtime

`examples/walk/walk_gameplay.c` содержит игровой код Windows/Linux walk и
Android NativeActivity: выбор актёра, ввод, шаг 128 Гц, камера, правки блоков
и перенос начала отсчёта. Оконные оболочки оставляют себе ввод устройства,
часы, накопитель времени, графические ресурсы, меши, UI и проверочный сценарий.
Общие исходники компилируются один раз в `laiue_walk_common`; это внутренняя
библиотека примера, не новый модуль или установленный SDK API.

`WalkGameplay` принадлежит приложению и остаётся по одному адресу всю сессию.
Его нельзя копировать или обнулять после `Init`: callbacks ссылаются внутрь
состояния, а физические тела владеют памятью координат. `Release` идемпотентен
и вызывается до выгрузки host. Таблицы сервисов заимствуются вместе с реальным
размером, возвращённым host; наличие callback проверяется и по этому размеру,
и по `structSize`, и по ABI. У каждой сессии свой `WalkPhysicsContext`.

При инициализации предпочитается рэгдол. Запасной кинематический контроллер
создаётся только при его отсутствии. Без обоих остаётся явно ограниченный
режим статического мира. Без sparse provider доступна генерируемая земля;
редактирование требует провайдера, различающего отсутствие override и явный
воздух. Неполная обычная конфигурация допустима, а сценарий требует полный
набор возможностей. Ошибка уже работающего провайдера останавливает сессию,
не подменяет актёра и не превращает непрочитанный блок в проходимый воздух.
`WalkGameplayHealth` позволяет оболочке проверить ошибки после meshing.

Порядок кадра: ориентация и вид, `SubmitInput`, до восьми фиксированных шагов,
`Camera`, `Edit`, обновление камеры при успешной правке, меши и показ кадра.
Сценарий подаёт отдельный ввод на каждый фиксированный шаг. Аналоговое движение
ограничено кругом, сохраняет силу отклонения и зависит от горизонтального
направления камеры, в том числе при взгляде вверх или вниз. Принятые импульсы
сбрасываются у отправителя и сохраняются до потребления; один прыжок не
повторяется на нескольких шагах. `ResetInput` очищает управление при потере
фокуса, сохраняя мир, позу, камеру, выбранный материал и счётчик шагов.

Snapshot связан с владельцем и ревизией. Изменение игры делает прежнюю камеру
непригодной для правки; отвергнутый snapshot не расходует импульс. BREAK идёт
перед PLACE, который видит уже изменённый мир. Пространственные координаты
хранят целые блоки отдельно от дробной части; `SpatialDelta` не переводит
огромные абсолютные позиции во float. Рэгдол переносится по всем трём осям
без копирования owned bodies. Неудачная операция откатывает изменённые тела;
ошибка самого отката переводит runtime в `INCONSISTENT_STATE` и запрещает
дальнейшую симуляцию. Кинематическая ветка пока использует V1 с XY-ячеками
и int32 voxel Z; миграция на V2 остаётся отдельной задачей.

На Android пересоздание поверхности меняет только presentation. Мир и актёр
живут до завершения приложения. Возвращение фокуса очищает старый ввод и
накопленное время; отказавший runtime не запускается повторно. Проверки
`laiue.example.walk_gameplay`, `walk_runtime`, `walk_visuals` и
`laiue.physics.ragdoll` дополняются настоящими оконным и Android-сценариями
из [walk_scenarios.md](walk_scenarios.md).

`walk --smoke` проверяет 32 оконных кадра и завершает собственный loop без
эмуляции пользовательского ввода. `tools/test_walk_fallback.ps1` проверяет
отдельные копии SHARED runtime без voxel, без physics и без обоих актёров.
Исходный runtime сохраняется; эти проверки не заменяют GPU-снимки полного
сценария. Встроенные desktop backends поддерживают SHARED modules; STATIC
desktop профиль требует EXTERNAL adapter и здесь не заявляется.
