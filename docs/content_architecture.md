# Архитектура содержимого

`content` — небольшая библиотека каталога, а не универсальный resource
manager. Она отвечает за безопасные имена, соответствие расширений
каталогам, перечисление файлов и хранение выбора активного пака.

Runtime-потребители используют две категории:

| Категория | Форматы | Потребитель |
|---|---|---|
| шейдеры | `.ls`, пакет `.lsp` | `render` |
| текстуры | одиночная `.lt`, каталог `.ltp` | `render` |

Данные прикладных систем хранятся и версионируются самими приложениями; их
не следует добавлять в `content` только ради общего каталога.

## Граница ответственности

`content` выполняет только операции, общие для категорий:

- создаёт явный `LaiueContentCatalog` с выбранным приложением root;
- проверяет имя до построения пути;
- перечисляет сущности одного точного формата;
- строит путь внутри каталога категории;
- читает и записывает `active.txt` для эксклюзивного пака.

Он не разбирает содержимое текстур, DXBC и семантику материалов. Форматы и GPU
ресурсы принадлежат `render`; поэтому каталог не участвует в кадре и не
владеет renderer handles.

## Активация

У каждой визуальной категории активен максимум один пак. UTF-8-имя хранится
в `<category>/active.txt`; пустой или отсутствующий файл выбирает встроенный
fallback. Смена значения сама по себе не создаёт GPU-ресурсы: приложение
решает, когда безопасно попросить renderer перечитать pack.

Неверный pack не должен повреждать уже созданные ресурсы. Renderer полностью
проверяет новый файл, создаёт replacement и только затем переключает GPU
state. При hot reload ошибка сохраняет прежний рабочий ресурс; при первой
подготовке без валидного выбранного пака используется встроенный fallback.

Процессный default catalog с root рядом с executable сохранён для
совместимости. Новое приложение удерживает явный каталог: так тесты, editor,
portable installation и несколько профилей не зависят от скрытого current
directory или process-global пути.

## Доверие и границы

Имена отклоняются, если содержат абсолютный путь, separators, `..`,
управляющие символы, зарезервированные Windows names либо неоднозначное
окончание пробелом/точкой. Loader каждого формата проверяет magic, version,
counts, offsets и полный размер до allocation и обращения к payload.

Шейдерный байткод выполняется GPU-драйвером и должен поступать из доверенного
источника. Структурная проверка файла не превращает внешнее содержимое в
безопасный код.

Нативные `.lmp` не являются ещё одной категорией `content`: у выполняемого
кода другой trust boundary и отдельный жизненный цикл. Их формат и ABI
описаны в [modding.md](modding.md).

Точные раскладки находятся в [content_formats.md](content_formats.md),
[shaderpacks.md](shaderpacks.md) и [texturepacks.md](texturepacks.md).
