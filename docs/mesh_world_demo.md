# Демо мира на мешах

`examples/mesh_world` — самостоятельный клиент публичных таблиц
`laiue.model`, `laiue.mesh_world`, `laiue.mesh_world_render` и графического
устройства V2. Он загружает модели из пака, потоково заполняет клетки
землёй и деревьями, двигает игрока через `moveBox` и передаёт рендереру
координаты относительно камеры. Вокселей, чанковой геометрии и прямых
вызовов D3D12/Vulkan в примере нет.

## Сборка и запуск

На Windows из x64 Developer Shell:

```powershell
cmake --preset windows-msvc -DLAIUE_BUILD_EXAMPLES=ON
cmake --build --preset windows-msvc-debug --target laiue_mesh_world_demo
build/windows-msvc/bin/Debug/laiue_mesh_world_demo.exe
build/windows-msvc/bin/Debug/laiue_mesh_world_demo.exe --headless 12
ctest --preset windows-msvc-debug -R 'laiue[.]mesh_world[.]demo' --no-tests=error
```

На Linux с Vulkan, X11 и программным драйвером Mesa:

```sh
cmake --preset linux-vulkan-x11-walk
cmake --build --preset linux-vulkan-x11-walk-release --target laiue_mesh_world_demo
build/linux-vulkan-x11-walk/bin/Release/laiue_mesh_world_demo
VK_DRIVER_FILES=/usr/share/vulkan/icd.d/lvp_icd.json \
  build/linux-vulkan-x11-walk/bin/Release/laiue_mesh_world_demo --headless 12
xvfb-run -a build/linux-vulkan-x11-walk/bin/Release/laiue_mesh_world_demo --frames 12
```

`--headless N` выполняет ровно N кадров без окна и завершается кодом 0
при успехе. Перед ними он проверяет опору игрока, потоковую генерацию
в точке `(10¹², −10¹², 0)` клеток и согласованный rebase. В каждом кадре
диагностического режима выполняются шесть шагов движения по 1/60 секунды.
При доступном Vulkan кадры проходят `setCamera`, `beginFrame`, adapter
`submit` и `endFrame` настоящего устройства; камера устанавливается до
начала кадра, и непустая геометрия должна попасть хотя бы в один кадр.
Демо проверяет отправку геометрии и завершение кадров. Эталонные пиксели
отдельно проверяют graphics geometry tests через optional V2 readback.

При сборке без Vulkan (например, D3D12-only) либо при удалении графического
модуля внутреннее контрольное устройство принимает буферы адаптера.
Проверяются загрузка пака, коллизии, rebase, непустые draw items и
освобождение всех буферов. Сообщение явно называет такую проверку
`CPU geometry`; оно не утверждает, что GPU нарисовал кадр. Наличие
Vulkan-провайдера с неработающим устройством — ошибка с кодом 1.

`--frames N` открывает настоящее окно, рисует N кадров и закрывает его.
Это строгая проверка оконного пути для Xvfb/CI: отсутствие рабочего окна
или графического устройства даёт код 1. Опции `--frames` и `--headless`
взаимоисключающие. N — целое число от 1 до 100000; некорректные аргументы
дают код 2. `--help` выводит краткую справку.

## Управление

| Клавиша | Действие |
|---|---|
| W/A/S/D | ходьба относительно направления камеры |
| мышь | поворот камеры при захваченном указателе |
| Space | прыжок с земли |
| Shift | бег |
| E | включить/выключить захват указателя |
| F7 | полноэкранный режим без рамки |
| Esc | закрыть окно |

Потеря фокуса сбрасывает состояние ввода и отпускает указатель;
для возобновления обзора нажмите E. Диагональное движение нормируется.
Игрок — коробка 0,6×0,6×1,8 м; столкновения и скольжение выполняет
`moveBox`, гравитацию и фиксированный шаг задаёт приложение.

## Пак и корень содержимого

Сборка копирует компактные собственные CC0-модели рядом с исполняемым
файлом:

```text
assets_mesh_world/
  LICENSE.txt
  models/
    active.txt       # Demo.lop
    Demo.lop/
      ground.obj
      tree.obj
```

Корень выбирается в следующем порядке: `--assets ROOT`, переменная
`LAIUE_MESH_WORLD_ASSETS`, каталог `assets_mesh_world` возле executable.
Текущий рабочий каталог не влияет на default root. ROOT — каталог,
содержащий `models/`, а не сам `.lop`. Например:

```powershell
laiue_mesh_world_demo.exe --assets "D:/my-content" --headless 12
```

`models/active.txt` выбирает произвольный `.lop`-пак, в котором приложение
ищет имена `ground` и `tree`. Пак можно заменить без пересборки. OBJ
загружается в осях Y-вверх и преобразуется модельным сервисом в Z-вверх;
цвета вершин дают траву, кору и листву, а `COL_trunk` задаёт отдельный
коллайдер ствола. Крона видна, но не блокирует игрока.

Сервис поддерживает также готовые `.lo` и исходные `.obj.lo`-кэши:

```sh
laiue_modelc tree.obj tree.lo
```

Без `tree.obj` сервис загрузит `tree.lo` из того же пака. Пока OBJ есть,
он имеет приоритет; порядок меняется через `models/formats.txt`, как
описано в [паках моделей](modelpacks.md). Кэш может появиться рядом
с исходником; default root использует build-копии и не меняет repository.
Каталог на чтение тоже поддерживается.

## Потоковая генерация и ограничения

В каждой клетке поверхности размером 16 м callback размещает плитку земли
и два дерева. Хэш абсолютных X/Y определяет их положение, высоту и
поворот при любом знаке координат; возвращение в ранее выгруженную
клетку восстанавливает тот же результат. Плитки образуют бесконечную
плоскость X/Y. Прикладной генератор оставляет прочие абсолютные Z-клетки
пустыми; сам mesh world допускает движение и размещение по всем трём
осям. Радиус streaming и отрисовки — 48 м, лимит мира — 8192 instances,
лимит адаптера — 1024 vertex/index buffers суммарно.

При native-index/instance capabilities плитки земли используют общую
shaded VB/IB-пару и группируются в GPU instance draws. Деревья с поворотом
или неодинаковым масштабом сохраняют запекание по ячейке и материалу.
Старое устройство либо короткая таблица callbacks использует прежнее
запекание всего мира. Обычный `draws` остаётся полным представлением сцены;
оконный путь использует optional adapter `submit`, когда он доступен.

После ухода дальше восьми клеток приложение останавливает свои
последовательные операции, rebases мир, игрока и origin provider.
Рендер всегда вычитает близкое к камере начало до преобразования
разности клеток во float. Матрица камеры описывает положение ноль;
`draws` выдаёт `originRelative` относительно её положения. Ни origin,
ни абсолютные int64-координаты не передаются в графическое устройство.

Пример использует существующие оконные/вводные providers Windows и X11.
Для Wayland, macOS, Android и iOS новых оконных оболочек он не добавляет;
там доступен только диагностический путь в поддерживаемом профиле.
Headless Vulkan требует работоспособный Vulkan loader/driver.

В shared-сборке executable линкуется с bootstrap, а optional DLL/SO
загружает явным частичным профилем. Удаление window переводит обычный
запуск в ограниченную диагностику; удаление input оставляет окно и
рисование без управления. Без graphics проверяется CPU-геометрия;
без mesh_world_render сохраняются загрузка моделей и движение, без
mesh_world отключается размещение/коллизии, без model отключается
генерация моделей. Без content остаётся явная загрузка OBJ из
`models/Demo.lop` в выбранном ROOT. Сообщение сообщает об отключённой
возможности, и сохранившиеся независимые возможности продолжают работу.
В static-профиле те же providers регистрируются таблицами API при сборке.

`laiue.mesh_world.demo_world` отдельно проверяет одинаковые результаты
provider до/после rebase, отрицательные и большие координаты, полную
запись клетки, опору игрока и скольжение вдоль ствола.
