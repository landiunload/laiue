# Build-time слияние compound-коробок: работа исполнителя

Эта заметка принадлежит ограниченной задаче по структурализму collision-формы:
уменьшить число детей `VoxelRigidCompoundShape`, не меняя объединение
геометрии. Зона записи: `src/physics/compound_shape.c`,
`src/physics/compound_shape.h`, `tests/compound_shape_test.c`,
`docs/compound_shape_work.md`. Root владеет CMake, игрой и всеми
`rigid_body.c/h`; они здесь не тронуты. Сборка и коммит не выполнялись.

## Что сделано

Новый публичный контракт без изменения существующих структур и ABI:

```c
bool VoxelRigidCompoundMergeBoxes(const VoxelRigidCompoundBox *boxes,
                                  uint32_t count,
                                  VoxelRigidCompoundBox *outBoxes,
                                  uint32_t capacity,
                                  uint32_t *outCount);
```

Заголовок `src/physics/compound_shape.h` включает `physics/rigid_body.h` и
использует `LAIUE_PHYSICS_API`, `VoxelRigidCompoundBox` и
`VOXEL_RIGID_COMPOUND_MAX_BOXES` (256). Реализация — в
`src/physics/compound_shape.c`.

Это инструмент **сборки формы**, а не шаг симуляции. Он ничего не выделяет
(ни heap, ни OS), не имеет изменяемого глобального состояния, детерминирован
и нормализует FP-режим через `VoxelPhysicsConfigureThread()` до арифметики.
Материал и масса входа не участвуют: слияние чисто геометрическое.

## Контракт и валидация

- `boxes`, `outBoxes`, `outCount` не `NULL`; `1 <= count <= 256`;
  `capacity >= count`.
- Каждая входная коробка: конечные центр и положительное конечное
  полуребро, конечные невырожденные границы `center ± halfExtent`
  (схлопывание в точку и переполнение отклоняются).
- Коробки строго не перекрываются; касание гранями перекрытием не считается.
- `boxes == outBoxes` разрешено ровно для полного in-place совмещения.
  Частично перекрывающиеся входной/выходной диапазоны отклоняются, как и
  `outCount`, указывающий в любой из буферов.
- Любой отказ возвращает `false` и **не пишет** ни `outBoxes`, ни `*outCount`.
- На успехе `*outCount <= count`; если слияний нет, layout входа сохраняется
  побитово (`*outCount == count`).

## Алгоритм

1. Превалидация указателей, `count`, `capacity` и aliasing.
2. `VoxelPhysicsConfigureThread()`, затем проверка каждой коробки и
   попарное отклонение строгих перекрытий — всё до первой записи.
3. Копирование входа в выход (пропускается при точном in-place) — после
   этого отказать уже нельзя, поэтому частичной записи не бывает.
4. Повторные проходы по осям `0,1,2`; в стабильном порядке пар `i < j`
   остаётся меньший индекс, удалённый компактится. Пара сливается только
   если по двум другим осям обе границы совпадают точно и по выбранной оси
   грани смыкаются точно (`lower.max == upper.min` или наоборот).
   Никаких допусков, заполнения зазоров и дырок.
5. Новые `center`/`halfExtent` обязаны точно восстановить объединённые концы
   (`center - half == low`, `center + half == high`), иначе слияние
   пропускается: на огромных координатах представимость не теряется.
   Проходы повторяются, пока есть слияния.

Каждое слияние — точное объединение двух неперекрывающихся гране-смежных
коробок, поэтому объединение всего набора сохраняется побитово (границы
считаются теми же `center ± halfExtent`, что и в collision-геометрии).

## Что проверяет тест

`tests/compound_shape_test.c` — standalone no-CRT тест (все буферы static,
entry общий `LAIUE_TEST_ENTRY`, буферы не растят кадр стека):

- отказ по `NULL`, `count == 0`, `count > MAX`, `capacity < count`;
- отказ по NaN/Inf центра и полуребра, нулевому/отрицательному полуребру,
  схлопнутым и переполненным границам; выход и `*outCount` неизменны;
- отказ по строгому перекрытию; касание гранями принимается и сливается в
  точную объединённую коробку;
- `capacity > count` и точный in-place дают тот же результат, что и
  out-of-place; частичное перекрытие диапазонов и `outCount` внутри буферов
  отклоняются без записи;
- девять блоков «Г»/L9 схлопываются ровно в 2 коробки, 16-блочная плита — в
  1; связанный зигзаг-лестница остаётся в 3 шага и вогнутым; впадина «Г»
  пуста, плечи сплошные; occupancy совпадает по всей сетке образцов;
- детерминированный повтор, совпадение бит за битом; отсутствие слияний
  сохраняет layout входа;
- положительные/отрицательные координаты (сдвиг через ноль) сохраняют
  объединение;
- огромные координаты: при 2^51 точное слияние проходит и восстанавливает
  концы, при 2^53 (шаг 2.0) невосстановимое слияние пропускается и layout
  не меняется;
- объём, COM и полный обратный тензор инерции совпадают у исходных детей и
  слитой формы (консервативный допуск), COM сверяется с аналитическим
  `(10/9, 0, 10/9)`;
- враждебный MXCSR/FPCR: результат побитово равен нормальному, окружение
  нормализовано.

## Ограничения

- Жадное слияние даёт максимальный относительно правила fixed point, но не
  обязательно единственное разбиение: разные порядки осей могут дать разные
  наборы коробок с одинаковым числом/объединением. Контракт фиксирует
  порядок (оси 0,1,2, пары `i < j`), поэтому результат воспроизводим.
- Слияние сохраняет только форму объединения; материал и масса — забота
  вызывающего.
- Сборка, запуск теста и интеграция не выполнялись в этой задаче: это зона
  root.
