# Звукопаки

Звукопак — каталог `sounds/<name>.lap` с файлами `.la` внутри. Активное
UTF-8-имя пака хранится в `sounds/active.txt`. Это только имя каталога:
запрещены separators, управляющие символы, Windows device names и
конечные пробел/точка.

Обязательного набора звуков нет. Имена придумывает приложение, движок
лишь отдаёт клип по имени, поэтому **заменить любой звук — значит
положить в свой пак файл с тем же именем**:

```text
sounds/
  active.txt          -> Mod
  Base.lap/
    step.la
    break.la
    music.la
  Mod.lap/
    step.la           <- звучит вместо Base.lap/step.la
```

Пак не наследует содержимое другого пака: активен ровно один каталог, и
звук, которого в нём нет, вернёт `AUDIO_PACK_LOAD_SOUND_NOT_FOUND`.
Решение о запасном варианте принимает приложение — движок не угадывает.

## Загрузка

```c
AudioPackLoadStatus status = AUDIO_PACK_LOAD_NOT_ATTEMPTED;
AudioClip* step = AudioClipLoadFrom(device, catalog, L"step", &status);
```

Имя звука проверяется как отдельная сущность содержимого, поэтому выйти
за пределы пака через `..` или разделитель каталогов нельзя. Клип
принадлежит вызывающей стороне и живёт независимо от голосов.

Приложение вправе не пользоваться каталогом вовсе:
`AudioClipLoadFile` читает произвольный путь, а `AudioClipLoadMemory`
разбирает `.la` прямо из памяти — для архивов, сети и app bundle.

`AudioPackEnumerateSoundsFrom` перечисляет звуки активного пака: это
позволяет приложению узнать, что в паке есть, не зная имён заранее.

## Формат LA

Все числа little-endian. Header занимает 24 байта:

| Offset | Тип | Значение |
|---:|---|---|
| 0 | `u32` | magic `LAS1` (`0x3153414C`) |
| 4 | `u16` | version = 1 |
| 6 | `u16` | header size = 24 |
| 8 | `u16` | channelCount: 1 или 2 |
| 10 | `u16` | encoding: 0 — PCM16, 1 — ADPCM |
| 12 | `u32` | sampleRate, 1000..384000 |
| 16 | `u32` | frameCount, 1..67108864 |
| 20 | `u32` | payloadBytes |
| 24 | — | payload |

`payloadBytes` обязан точно совпадать с размером, вычисленным по
`frameCount`, `channelCount` и `encoding`; расхождение отвергается как
повреждение. Runtime не декодирует WAV, MP3 и прочие контейнеры —
подготовка `.la` выполняется внешним offline-инструментом, ровно как у
текстурпаков.

### PCM16

Сэмплы `int16` little-endian, чередование по каналам:
`frameCount × channelCount × 2` байта.

### ADPCM

IMA ADPCM, 4 бита на сэмпл — вчетверо компактнее PCM16. Каналы лежат
последовательно, а не чередуются: клип распаковывается целиком при
загрузке, точки синхронизации не нужны, а декодировать так проще.

Для каждого канала подряд:

| Тип | Значение |
|---|---|
| `i16` | начальный predictor |
| `i16` | начальный stepIndex, 0..88 |
| нибблы | `ceil(frameCount / 2)` байт |

В байте нибблов младший полубайт — чётный кадр, старший — нечётный.

Начальный `stepIndex` лежит в файле не случайно: кодировщик обязан
выбирать его по первым перепадам сигнала. Со шага 7 декодер догоняет
быстрый сигнал десяток отсчётов, и весь этот разгон слышен как щелчок в
начале звука. На проверочной волне выбор шага по сигналу уменьшает
худшую ошибку с 2027 до 68 единиц из 32768.

## Границы

Движок не знает, что такое «шаг» или «удар»: список звуков —
принадлежность приложения. Расстояние, затухание и реверб тоже
принадлежат ему; движок отвечает за громкость, панораму и скорость.
Подробнее о микшере — в [audio.md](audio.md).
