# Твёрдые тела: корректность, воспроизводимость и оптимизация

Этот документ относится к вращающимся коробкам `VoxelRigidBody`, а не к
AABB-контроллеру персонажа `VoxelBody`, описанному в [physics.md](physics.md).
Шаг rigid-body симуляции фиксирован: `1/128` секунды. Глобальные координаты и
скорости сохраняют представление произвольной точности; геометрия контактов,
ориентации и импульсы рассчитываются в локальных `double`.

## Что исправлено

- Спящее динамическое тело больше не становится бесконечно тяжёлой опорой.
  Столкновение с активным телом пробуждает связанный контактами набор тел
  обходом очереди до сбора ограничений. Все разбуженные тела получают
  гравитацию текущего шага, сохраняют конечные массу и инерцию.
- Сон принимается для целого контактного острова: недостаточно, чтобы
  успокоилось одно тело внутри движущейся кучи. При гравитации острову нужна
  связь с миром. При удалении внешней опоры приложение обязано вызвать
  `VoxelRigidBodyWake` для затронутых тел: полностью спящий мир не опрашивает
  произвольные изменения callback сам.
- Плечи, направления, эффективные массы и отклики на единичный импульс
  подготавливаются один раз перед итерациями. Коэффициент упругости применяется
  к исходной относительной скорости контакта, а не пересчитывается по уже
  исправленным скоростям каждой итерации.
- Трение накапливает две касательные составляющие. Их общий вектор
  ограничивается диском Кулона `|lambda_t| <= mu * lambda_n`; к телам применяется
  только изменение накопленного импульса. Отдельное ограничение каждого
  приращения или каждой оси не обеспечивает этот закон.
- Размер ячейки broad phase учитывает AABB после вращения. В OBB SAT
  минимальная ось «ребро–ребро» теперь может задавать нормаль столкновения,
  а не только отбрасывать разделённые коробки.
- Квадратный корень вычисляется в аппаратном `binary64`, без начального
  преобразования в `float`, которое могло переполняться или терять малые числа.
  При переполнении буфера контактов шаг сообщает ошибку, а не решает молча
  усечённый набор. Ошибку нужно обрабатывать: API не обещает отката уже
  выполненных изменений шага.

Подготовка ограничений и накопленные импульсы соответствуют подходу
[решателя Box2D](https://github.com/erincatto/box2d/blob/main/src/contact_solver.c).
Совместный сон и пробуждение описаны в
[документации Jolt](https://jrouwe.github.io/JoltPhysics/) и
[разборе островов Box2D](https://box2d.org/posts/2023/10/simulation-islands/).
Это ориентиры реализации, а не утверждение эквивалентности этих движков.

## Что подтверждают тесты

`laiue.physics.rigid_solver` проверяет упругость, сохранение линейного импульса,
границу трения, нормаль реберного контакта и отказ при переполнении контактов.
Replay выполняет 2048 шагов для восьми тел, включая импульс на заданном тике.
Четыре прогона сравнивают повторный запуск, перестановку массива тел и
намеренно изменённый FP-режим. В хеш входят все числовые поля тел, точные лимбы
координат/скоростей, ориентация, параметры массы, материала и сна в порядке
`stableId` на каждом шаге; адреса и padding не входят.

В проверенном прогоне хеш `0xfb1c9d5a02972c16` совпал в Windows с clang-cl и
MSVC, Debug и Release, а также в Linux GCC Debug и Release. Это наблюдаемый результат
данной версии, не доказательство для непроверенных ARM, Apple, мобильных или
закрытых консольных сборок. Старый хеш `0x4486debc2d00fab7` проверяет другой,
AABB-контроллер; его успех не заменяет rigid-body replay.

`laiue.physics.rigid_cache` дополнительно проверяет размеры и пересечение
буферов, reset, пробуждение с конечной массой, удаление опоры и сохранение
локальных якорей при общем горизонтальном rebasing. Его отдельный эталон
`0x01d0a286ff9911da` совпал в тех же шести конфигурациях. Тесты движка:
25/25 в каждой из них, включая новый `rigid_broadphase`; Windows и Linux
проверяют разные платформенные
наборы. Игра: 6/6 в четырёх Windows-конфигурациях, 3/3 в Linux GCC
Debug/Release. Windows ARM64 проверяется отдельной кросс-сборкой, не запуском.

В Simulation of sins спавн перенесён на фиксированные тики: целочисленная
фаза даёт 100 появлений на 128 шагов без накопления `0.01` в `double`.
Одинаковый seed и одинаковые входы по тикам проверяются при различной
группировке шагов по кадрам. Полное воспроизведение камеры, пользовательского
ввода и всех систем игры пока не реализовано.

Один seed сам по себе не задаёт replay: нужны одинаковые версия движка,
начальное состояние, порядок команд, PRNG и последовательность входов по
тикам. Fast-math, различающиеся FMA и библиотечная тригонометрия могут нарушить
битовый контракт. Эти ограничения объясняют
[Box2D](https://box2d.org/posts/2024/08/determinism/) и
[Rapier](https://rapier.rs/docs/user_guides/templates/determinism/).

## Реализованный кэш импульсов

`VoxelRigidBodyStepCached` принимает принадлежащий приложению
`VoxelRigidContactCache`. Размер запрашивается через
`VoxelRigidContactCacheBytes`; скрытых выделений памяти нет. Контакты
сопоставляются детерминированно по stableId пары, двум локальным якорям
(допуск 0.01 блока) и нормали (dot не меньше 0.995). Один старый контакт
используется не более одного раза. После подготовки всех restitution targets
сохранённый импульс проецируется в новый базис и ограничивается диском Кулона.
Затем выполняются прежние восемь итераций: ни масса, ни число ограничений
ради скорости не урезаются.

Кэш — дополнительная начальная оценка решателя, а не готовый ответ.
При конечном числе итераций cached и uncached траектории могут различаться;
каждая проверяется своим replay. Изменение мира, телепортация, параметры
формы/массы/материала/решателя и повторное использование ID требуют Reset.
Обычный общий rebasing и внешние импульсы сброса не требуют. При изменении
опоры Reset не заменяет явного пробуждения затронутых спящих тел.

История кэша и момент его сброса входят в состояние replay. Игра использует
этот API и сбрасывает кэш при детерминированном росте ёмкости массива.
Переносимый формат сохранения кэша пока не задан. Память — примерно
1.8 KiB на тело **ёмкости**, дополнительно к временному буферу шага.
В `StepCached` сетка строится заново; `StepIndexed` использует описанное
ниже постоянное дерево. Геометрия контактов в обоих путях пересчитывается:
это ещё не persistent manifold с сохранением topology.
Ориентиры:
[Jolt contact cache](https://github.com/jrouwe/JoltPhysics/blob/master/Jolt/Physics/Constraints/ContactConstraintManager.cpp)
и [Bullet persistent manifold](https://github.com/bulletphysics/bullet3/blob/master/src/BulletCollision/NarrowPhaseCollision/btPersistentManifold.h).

### Замеры, 6 сентября 2026

Плотный benchmark сравнивает 512/2048 активных тел с кэшем и без него,
одинаковые начальные данные, восемь итераций и отключённый сон. Пять samples
сбрасываются перед измерением одинаковых восьми тиков; число контактов и
хеш состояния совпадают между samples внутри каждого режима. Добавлен
сценарий 512 тел после 128 подготовительных тиков.

Первый парный Windows clang Release замер дал 1.266/1.469 ms для 512 тел,
5.382/5.744 ms для 2048 и 1.370/1.502 ms для подготовленных 512
(uncached/cached). Кэш добавляет работу и **не доказал ускорение шага**.
Нельзя считать различающиеся траектории строго одинаковым workload.
Последующая локальная правка убирает лишнее деление в проверке трения и
повторное вычисление контактной скорости при нулевом изменении импульса;
оба эталона replay и шесть dense-хешей сохранены. Устойчивый процент
ускорения этой небольшой правки не установлен.

Обратная масса также копируется в рабочие данные шага рядом со скоростями:
применение импульсов больше не обращается к публичному массиву тел только
ради этого поля. Порядок `(direction * magnitude) * inverseMass` сохранён,
стоимость рабочего буфера выросла на 8 bytes на тело. В парном спавнере
6144 тика остались точно эквивалентны; устойчивый процент ускорения этой
правки не установлен, и решение проблемы плотной кучи ей не приписывается.

Реальный 60-секундный прогон Simulation of sins с кэшем дошёл до 4179 тел,
3199 из них бодрствовали; последний интервал — 13314 контактов, 12397
переиспользованных импульсов и 24.50 ms на тик. При нескольких тиках за кадр
это около 312 ms физики/кадр, а не приемлемая скорость. Этот прогон не
является парным A/B доказательством ускорения и не подтверждает возможность
сотен тысяч одновременно контактирующих активных тел.

## Постоянный пространственный индекс

`VoxelRigidBodyStepIndexed` принимает `VoxelRigidBroadphase` и необязательный
кэш импульсов. Индекс вынесен в отдельный `rigid_broadphase.c`: пул узлов
с балансировкой по высоте, ссылки по индексам, обход без рекурсии и без
скрытых выделений памяти. Буфер принадлежит приложению, размер запрашивается
через `VoxelRigidBroadphaseBytes` (примерно 148 bytes на тело ёмкости).
Метаданные нельзя менять вручную. Использованы общие принципы
[dynamic AABB tree Box2D](https://box2d.org/documentation/group__tree.html),
адаптированные к 3D, binary64 и существующему порядку контактов LAIUE.

Тело переустанавливается в дереве, только когда его AABB выходит за сохранённую
оболочку с запасом 0.05 блока либо старая оболочка стала чрезмерно большой
после уменьшения формы. При равной высоте поворачиваемых ветвей выбирается
меньшая объединённая коробка: баланс высот сам по себе не гарантирует хорошего
пространственного разделения. При обновлении предка выполняется не более
одного дополнительного обмена ветвей, строго уменьшающего их метрику и
сохраняющего AVL-баланс. Запрос обходит parent links без стека, выделений
и рекурсии.
Спящие тела остаются доступными запросам
активных тел; механизм пробуждения и конечные массы не меняются.

Перед запросами шаг синхронизирует все текущие границы, удаляет неактивные
тела и хвост после сокращения массива. Перестановка массива, смена формы,
телепортация и rebasing не оставляют старую геометрию в дереве. После
полностью спящего шага синхронизация отложена до следующего бодрствующего
шага; она обязательно выполняется до поиска контактов. `proxyCount` поэтому
описывает последнюю синхронизацию, а не произвольно изменённый извне массив.

Дерево возвращает кандидатов в собственном порядке, но перед использованием
они фильтруются и сортируются по прежним `(cell.x, cell.y, cell.z, stableId)`.
Размер legacy cell вычисляется прежней формулой вращённого AABB. Поэтому
исключение лишних кандидатов не меняет порядок импульсов или callbacks мира.
Сброс дерева хоть на каждом тике сохраняет физическое состояние. В отличие
от кэша импульсов, его topology не требуется сохранять для replay.

`laiue.physics.rigid_broadphase` сравнивает legacy/indexed состояния после
каждого тика, cached/uncached эталоны, перестановку массива, hostile FP,
удаление/добавление/замену тел, общий rebasing и пробуждение. Отдельный сценарий
полностью заполняет пул 32 телами, сокращает его до одного листа, заполняет
снова и выполняет 256 детерминированных изменений состава/форм/порядка.
Benchmark теперь сравнивает сетку и дерево для каждого режима кэша и требует
одинаковый конечный хеш в паре; количество кандидатов ожидаемо различается.

Реальная однородная куча пока лучше подходит сетке: парный headless-спавнер
Simulation of sins на 6144 тиках достиг 4800 тел с побитовым совпадением
состояний grid/tree после каждого тика, но дерево с обходом по parent links
было медленнее (последнее окно 23.30/33.69 ms на тик, grid/tree).
Игра оставляет сетку по умолчанию, дерево доступно явно для измерений.
Микротест на регулярной раскладке не заменяет этот сценарий.

Ограничение этапа: остаётся O(N) синхронизация и построение локальных данных
тел. Индекс устраняет полный rehash и часть поиска пар, но не стоимость
решения всех настоящих контактов. Детерминированный параллельный решатель
ещё не реализован.

## Следующие этапы: ещё не реализованы

Восстановление физического поведения не решило производительность большой
активной кучи. Уснувшие тела нельзя снова замораживать навсегда ради FPS.
Плотные ручные сценарии 512/2048 тел измеряют контакты при отключённом сне;
результаты разреженных или полностью спящих 100 000 тел не описывают такую
нагрузку. Дальнейшие этапы требуют отдельного контекста `persistent world`,
которым явно владеет вызывающее приложение:

1. **Устойчивая геометрия контактов.** Warm starting реализован выше, но
   геометрические feature IDs и постоянные manifolds ещё нет. При сокращении
   manifold нужно сохранять глубину и площадь опоры, а не первые найденные
   точки. Полезность изменения подтверждать устойчивостью/сходимостью и
   сопоставимым замером, не только количеством попаданий в кэш.
2. **Компактный активный набор.** Постоянный индекс реализован выше, но
   локальные данные тел пока проверяются целиком. Следующий этап — явное
   владение изменениями и компактный список активных данных вместо полного
   сканирования мира на каждом шаге. Реализация
   [Bullet DBVT](https://github.com/bulletphysics/bullet3/blob/master/src/BulletCollision/BroadphaseCollision/btDbvtBroadphase.h)
   демонстрирует раздельные деревья движущихся и неподвижных объектов.
3. **Канонический порядок и локальные регионы.** Полученные пары и контакты
   приводить к определённому порядку независимо от обхода индекса. Вычитать
   близкий физический origin в точной арифметике до преобразования в `double`.
   Выбор региона и перенос тел привязать к тикам, не к камере. Произвольная
   длина глобальной координаты не даёт произвольной точности локальному
   `double`; см. ограничения больших миров в
   [Jolt](https://jrouwe.github.io/JoltPhysics/).
4. **Детерминированные параллельные группы.** Независимые острова считать
   параллельно; большой остров разбивать на группы ограничений без совместной
   записи в одно тело, исполняя группы в фиксированном порядке с барьерами.
   Атомарный append сам по себе не задаёт порядок. См.
   [Jolt LargeIslandSplitter](https://github.com/jrouwe/JoltPhysics/blob/master/Jolt/Physics/LargeIslandSplitter.cpp)
   и [детерминированное объединение результатов Box2D](https://box2d.org/posts/2024/08/determinism/).
5. **Полные контакты с вокселями и CCD.** Заменить ограниченность проверки
   углов коробки полноценным пересечением формы с геометрией мира; для быстрого
   движения добавить swept/continuous collision с воспроизводимым выбором
   времени удара. Отключение контактов при экстремальной скорости и один
   дискретный шаг не защищают от туннелирования. Спекулятивные контакты также
   имеют допуски и артефакты, описанные в
   [Jolt PhysicsSettings](https://github.com/jrouwe/JoltPhysics/blob/master/Jolt/Physics/PhysicsSettings.h).

Каждый этап принимается отдельно: физические регрессии, replay, затем
сопоставимый профиль плотной сцены. Ни совпадающий хеш, ни высокая скорость
не являются самостоятельным доказательством отсутствия ошибок столкновения.
