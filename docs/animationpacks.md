# Паки анимаций

`laiue.animation` — самостоятельный переносимый модуль. Он загружает клипы
`.lk`, сэмплирует каналы, строит скелетную позу и выполняет CPU-скиннинг.
Рендер, мир, модели, звук и графическое устройство ему не нужны. `LAIUE_BUILD_ANIMATION=OFF`
убирает модуль из сборки. Приложение запрашивает таблицу `LaiueAnimationServiceV1`
по имени `laiue.animation`, ABI 1, либо получает её через
`LaiueAnimationGetStaticServiceV1`.

Пак — каталог `animations/<имя>.lkp`, клипы — файлы `.lk` внутри него.
Подкаталоги допустимы до восьми сегментов. Например, `loadFrom(catalog,
L"humanoid/walk", &status)` читает `humanoid/walk.lk` активного пака. Выбор
хранится в `animations/active.txt`; перечисление и активация используют
необязательный сервис содержимого `laiue.assets`. Пока существует только
собственный формат `.lk`, отдельных исходных импортёров и кэша нет.

Без provider-а остаются `loadMemory`, `loadFile`, sampling и skinning.
Отсутствующий, повреждённый или невыбранный ресурс пака возвращает пустой
нейтральный клип с `LAIUE_ANIMATION_FLAG_PLACEHOLDER` и причиной в `outStatus`.
Небезопасное имя и нехватка памяти возвращают `NULL`. Явная загрузка из файла
или памяти при любой ошибке возвращает `NULL`. Клипы неизменяемые, допускают
одновременное чтение и принадлежат вызывающему; освобождение выполняет
`service->release`. Списки освобождает `service->releaseList`.

Таблица каталога заимствуется на время жизни модуля. Hosted instance может
быть только один на process: атомарный create второго host-а получает отказ
до изменения provider-а первого. Rollback второго host-а не сбрасывает
первый; после stop/destroy первого можно загрузить модуль в другой host.
`LaiueAnimationSetContentService` предназначен для прямой интеграции и
вызывается после остановки всех пользователей. Lifecycle host-а и смена
provider-а не выполняются одновременно со служебными вызовами.

## Каналы и время

Канал содержит тип, `target`, интерполяцию и диапазон ключей. Для translation,
rotation и scale `target` — индекс joint; для scalar и texture frame это
непрозрачный application id. Повтор одного типа с тем же target запрещён.
Метаданные доступны через `getView` и `getChannel`; значения — через
`sampleChannel`. Отдельных имён костей в формате нет: связывание индексов со
скиннингом модели определяет приложение.

Ключи каждого канала строго возрастают по времени, лежат в `[0,duration]` и
хранят четыре `float` плюс отдельный `uint32_t frame`. Scalar использует
`value[0]`, translation/scale — первые три компонента, rotation — единичный
кватернион `(x,y,z,w)`. Значение до первого и после последнего ключа сохраняет
ближайший крайний ключ. STEP выбирает ключ с временем не больше заданного;
на точной границе выбирается новый ключ. LINEAR интерполирует числовые
значения, а кватернионы — нормализованной линейной интерполяцией с выбором
кратчайшей дуги (nlerp). Это не постоянная угловая скорость slerp.

Texture frame поддерживает только STEP; номер кадра никогда не проходит
через float и сохраняет весь диапазон uint32. Приложение проверяет его по
числу кадров своей текстуры. Анимированные GIF остаются в текстурпаках:
клип только выбирает их кадр.

Время передаётся в секундах как конечное `float`. При `loop == 0` оно
ограничивается `[0,duration]`, при loop оборачивается в `[0,duration)`;
отрицательное время оборачивается назад. Для нулевой длительности время
всегда нулевое. Деление остатка не приводит float к ограниченному integer,
поэтому даже `FLT_MAX` и очень короткие конечные длительности безопасны.
Повторный вызов с теми же входами даёт тот же результат в одной сборке;
побитовая одинаковость между разными CPU/compiler не является контрактом.

## Скелет и CPU-скиннинг

Joint хранит parent, исходный local TRS и affine inverse bind. Parent —
`UINT32_MAX` для корня либо индекс строго меньше текущего; несколько корней
разрешены, циклы исключены. Позу строит `samplePose`: сперва копирует bind
TRS, затем заменяет соответствующие компоненты из TRS-каналов, после чего
считает `global = parentGlobal * local` и `palette = global * inverseBind`.

Матрицы — affine row-major 3×4, действующие на column vector. Translation
лежит в элементах 3, 7, 11; это отдельный ABI и его нужно преобразовать к
раскладке используемого рендера. Вызывающий предоставляет три массива
ёмкостью jointCount: local TRS, global matrices, palette matrices. Массивы
не пересекаются; перекрытие отклоняется до записи. Для пустого клипа все
три могут быть NULL.

`skinVertices` читает четыре индекса и четыре веса на вершину, преобразует
позицию взвешенными palette matrices, нормаль — их inverse transpose, затем
нормализует нормаль. Даже индекс с нулевым весом должен попадать в palette.
Веса конечные, неотрицательные; сумма отличается от единицы не более чем
на 0.001 и дополнительно нормализуется при вычислении. Нулевой вектор
нормали остаётся нулевым. Отрицательный scale разрешён; нулевой scale ключа
запрещён, но переход между противоположными знаками может дать сингулярную
позу — её skinning отклонит. Inverse bind задаёт приложение; читатель
проверяет конечность, а skinning — обратимость используемых matrices.

На sampling и skinning нет allocation, I/O, логирования и CRT/libm.
Все выходные буферы принадлежат приложению. Pose при переполнении конечного
float возвращает 0 и оставляет выходные массивы в неопределённом состоянии.
Skinning сначала проверяет весь вычисленный результат и только вторым
проходом записывает выход, поэтому ошибка последней вершины не публикует
частичный mesh. Перекрытие input/output массивов и palette/output
отклоняется до записи. Это основа CPU-пути:
она заново считает inverse transpose для каждой ненулевой influence и
делает два прохода; SIMD batching, кэш нормальных matrices, blending клипов,
IK, root motion и GPU-скиннинг в текущую версию не входят.

## Формат `.lk`, версия 1

Все целые little-endian, `float` — IEEE 754 binary32. Указатели, native
struct padding и wchar не сериализуются. Заголовок — ровно 48 байт:

| Смещение | Поле |
| --- | --- |
| 0 | magic `LAK1` |
| 4 | uint32 version = 1 |
| 8 | uint32 headerBytes = 48 |
| 12 | uint32 точный размер файла |
| 16, 20, 24 | uint32 channelCount, keyCount, jointCount |
| 28 | float duration ≥ 0 |
| 32, 36, 40 | uint32 offsets таблиц channels, keys, joints |
| 44 | uint32 reserved = 0 |

Таблицы следуют сразу за заголовком строго в указанном порядке, без дыр и
хвоста. Channel — 20 байт: uint32 kind, target, interpolation, firstKey,
keyCount. Kind 1/2/3/4/5 означает translation/rotation/scale/scalar/texture
frame; interpolation 0/1 означает STEP/LINEAR. Каждый канал имеет минимум
один ключ, диапазоны ключей плотно следуют друг за другом.

Key — 24 байта: float time, float value[4], uint32 frame. Все floats,
включая неиспользованные компоненты, конечны. Joint — 92 байта:
uint32 parent, float translation[3], float rotation[4], float scale[3],
float inverseBind[12]. Квадрат длины quaternion лежит в `[0.999,1.001]`.
Лимиты: 4096 channels, 1048576 keys, 1024 joints, 64 МиБ на файл. Пустой
клип — допустимый заголовок с нулевыми counts; длительность может быть ноль.

Общий внутренний `media/animation.[ch]` реализует
`AnimationInspect → caller buffers → AnimationDecode` и обратный
`AnimationEncodedBytes → AnimationEncode`. Inspect проверяет magic,
версию, bounded counts, точный размер, offsets, всю иерархию и каждый ключ
до allocation. Decode повторяет inspection, проверяет caller capacities
и совпадение info, затем пишет записи. Перекрытие входного файла, metadata
и выходных массивов отклоняется до записи; encode также не пишет поверх
исходных records. Несовместимая версия явно возвращает
`ANIMATION_UNSUPPORTED_VERSION`, частичный файл не становится клипом.

Проверки: `laiue.media.animation_codec`, `laiue.animation.sampling`,
`laiue.animation.packs`; `laiue.fuzz.animation` прогоняет malformed и
корректные corpus seeds под libFuzzer/ASan/UBSan, включая canonical round trip.
