# Детерминированная физика и координаты

`laiue::physics` — переносимый allocation-free набор AABB-операций:
столкновение с вокселями, axis sweep, ground contact, защита края при
приседании и bounded broadphase для динамических коллайдеров. Интегратор,
fixed-step scheduler, силы и игровая модель тела принадлежат приложению.

## Детерминизм

Текущий битовый контракт ограничен x86_64/SSE2. Physics собирается без
fast-math и без FMA contraction; одинаковые входы, порядок fixed steps,
снимок callbacks и параметры должны давать одинаковый результат на
поддерживаемых MSVC, clang-cl, GCC и Clang. Это не обещание для ARM64 или
любой будущей платформы без отдельного эталонного прогона.

Динамические коллайдеры имеют ненулевой уникальный `stableId`. Solver
проверяет полный bounded batch, отклоняет дубликаты и сортирует максимум 32
элемента по `stableId`, поэтому порядок broadphase callback не меняет
narrowphase. Ошибка или truncation callback обрабатывается fail-closed.

Регрессионный тест выполняет 60 000 фиксированных шагов и сравнивает:

- повторный запуск с теми же входами;
- запуск с несколькими chunk-aligned rebasing по положительным и
  отрицательным осям;
- столкновения на обеих сторонах границы чанка;
- 100 000 повторных resting contacts без накопления битового drift;
- физику при абсолютном начале мира за диапазоном `int64_t`.

Эталонный x86_64-хеш версии 0.7 — `0x4486debc2d00fab7`. Изменение хеша
требует объяснения изменения физического контракта, а не автоматического
обновления константы.

## Бесконечный мир

Абсолютное начало мира хранится в `InfiniteCoord` произвольной точности.
Горячий путь `World` использует локальные `int64_t`, а положение активного
тела — локальные `double`. Поэтому точность физики зависит от расстояния до
текущего локального начала, а не от абсолютного расстояния во вселенной.

При `WorldRebase(world, shiftX, shiftY, shiftZ)` приложение в той же
остановленной simulation boundary вычитает тот же shift из каждой локальной
позиции тела:

```c
if (WorldRebase(world, shiftX, shiftY, shiftZ))
{
    bodyPosition[0] -= (double)shiftX;
    bodyPosition[1] -= (double)shiftY;
    bodyPosition[2] -= (double)shiftZ;
}
```

Сдвиг `World` обязан быть кратен `CHUNK_SIZE`. Streaming, meshing, physics и
provider users должны быть остановлены на время общей операции; иначе разные
подсистемы увидят разные локальные начала.

Render origin остаётся отдельным, ещё более близким к камере началом. Только
после вычитания render origin координаты сужаются до `float` и передаются GPU.

## Точность binary64

Перед collision query `VoxelBodyLocalRangeIsResolved` проверяет форму,
конечность координат и фактическое разрешение `collisionEpsilon`. Для
ненулевого epsilon solver требует, чтобы epsilon покрывал не менее четырёх
локальных ULP. Если margin больше не представим, collision API fail-closed и
не меняет позицию; приложение должно выполнить rebasing.

Для стандартного `collisionEpsilon = 0.001`:

| Локальный масштаб | ULP binary64 | Результат проверки |
|---:|---:|---|
| около 0 | примерно `2^-52` относительно значения | полный запас |
| `2^40` | `0.000244140625` | проходит: epsilon ≈ 4.096 ULP |
| `2^41` | `0.00048828125` | отклоняется |

На границе `2^40` максимальная ошибка округления одной локальной координаты
составляет примерно `0.0001220703125` единицы блока. Реальная длина зависит
от масштаба, который выбрало приложение; движок не приравнивает блок к метру.
Практически активные тела следует держать намного ближе к локальному нулю, а
не использовать предельный прошедший диапазон как рабочую зону.

Ненулевое движение, которое округляется обратно в исходную координату,
считается заблокированным без изменения позиции и без broadphase query.
Неверные shapes, неразрешимые координаты и неполные collider batches также
не разрешают пройти в непроверенную область.

## Что именно гарантируется

Гарантируется воспроизводимость collision primitives при одинаковом
simulation snapshot и поддерживаемом x86_64 toolchain. Сетевая задержка,
частота кадров, порядок внешних событий и синхронизация состояния не входят
в физический контракт. Приложение должно использовать фиксированный шаг,
стабильный порядок сущностей и один неизменяемый снимок мира на шаг.
