# Адаптивное instance-кольцо Vulkan

## Итог

Vulkan больше не резервирует фиксированные `16 МиБ` на каждый кадровый
слот. Инстансные данные идут в независимые host-visible storage-буферы:
первый чанк имеет размер `1 МиБ`, последующие создаются по мере нехватки
места, а общий бюджет слота ограничен `64 МиБ`. Чанки не уничтожаются до
уничтожения рендера, поэтому записанный в command buffer descriptor set
никогда не начинает ссылаться на освобождённый ресурс.

Один большой `VkBuffer` с заменой был сознательно не выбран: после записи
первого draw в командный список его descriptor set уже фиксирует старый
буфер. Замена потребовала бы копирования данных и отдельного контроля
времени жизни. Для каждого `(geometry block, frame slot, instance chunk)`
выделяется свой descriptor set; переключение чанка не меняет уже записанные
команды.

## Поток кадра

`RendererBeginFrame_Vulkan` сбрасывает только курсор текущего слота после
`vkWaitForFences`; количество созданных чанков и их ресурсы сохраняются.
`RendererDrawMeshInstances_Vulkan` резервирует непрерывный диапазон,
переходит к следующему чанку или создаёт его лениво, копирует инстансы и
выбирает descriptor set этого чанка. Все смещения выравниваются по
`minStorageBufferOffsetAlignment`, а размер одного вызова ограничен тем же
`64 МиБ` бюджетом.

Наборы чанков обновляются при загрузке текстурного пака. При освобождении
геометрического блока все его существующие наборы возвращаются в
descriptor pool. Пул заранее допускает худший случай: `64` блоков × `2`
кадровых слота × `64` чанка; фактически наборы выделяются только для
созданных чанков и используемых блоков.

## Проверка

Добавлен `tests/renderer_vulkan_instance_ring_test.c`. Тест выполняет
четыре draw-вызова по `200000` инстансов (`25,6 МиБ` при текущем формате),
шесть кадров с rollover обоих слотов, resize и resize обратно. Он сверяет
`drawCalls == 4` и полный `drawnQuads`, поэтому фиксированный старый буфер
не может пройти с молча потерянными вызовами.

Проверено на Windows x64 с Vulkan SDK и рабочим драйвером:

- Release: новый тест прошёл; полный CTest — `39/39`;
- Debug: новый тест прошёл; сборка без предупреждений;
- существующие offscreen, lifecycle, dual-backend и D3D12 instance-ring
  тесты также прошли.

Публичный `renderer.h`, экспортируемый ABI и формат `RendererMeshInstance`
не менялись. Linux/macOS/ARM64/консольные runtime-прогоны этой Vulkan-правки
на данном хосте отдельно не выполнялись; они требуют соответствующих SDK и
драйверов. Бюджет `64 МиБ` на слот остаётся защитным потолком: при его
исчерпании вызов корректно отбрасывается, как и раньше, но теперь порог
выше прежних `16 МиБ`.
