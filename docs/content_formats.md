# Форматы содержимого

| Назначение | Одиночный формат | Пак | Runtime-каталог |
|---|---|---|---|
| шейдеры | `.ls` | `.lsp` | `shaders/` |
| текстуры | `.lt` | `.ltp` | `textures/` |
| звуки | `.la` | `.lap` | `sounds/` |

Все три пака — каталоги. `.ls` — один скомпилированный shader stage,
`.lsp` — каталог стадий и манифеста. `.lt` — одна подготовленная
текстура, `.ltp` — каталог текстур. `.la` — один готовый к
воспроизведению звук, `.lap` — каталог звуков.

Внутри текстурпака и звукопака ресурс адресуется именем, которое вправе
быть путём с `/`: пак делится на подпапки. Расширение движок подбирает
сам и рядом со своим форматом принимает исходные — PNG, GIF и JPEG для
текстур, WAV и MP3 для звука.

Имена проверяются до построения пути. Запрещены абсолютные пути, `..`,
управляющие символы, зарезервированные Windows names и конечные
пробел/точка. В имени ресурса внутри пака разделителем служит `/`, и
каждый сегмент проверяется отдельно; сегментов не больше восьми. Один pack не смешивает форматы разных категорий.
Каталог отклоняет неоднозначный набор, если два имени отличаются только
регистром ASCII: такой набор нельзя одинаково адресовать на Windows и Linux.

## Шейдеры

Шейдерпак — каталог `shaders/<name>.lsp`:

```text
pack.lm
chunk_vs.ls       chunk_ps.ls
panorama_vs.ls    panorama_ps.ls
ui_vs.ls          ui_ps.ls
```

`pack.lm` объявляет версию контейнера и renderer contract. Допустимо
поставить непустое подмножество стадий; отсутствующие стадии берутся из
встроенного набора. Точный контракт — в
[shaderpacks.md](shaderpacks.md).

## Текстуры

Текстурпак — каталог `textures/<name>.ltp`. Имена текстур совпадают с
именами материалов приложения, которые оно задаёт через
`RendererSetMaterialNames`. Внутри лежат `.lt`, `.png` или `.gif`;
анимированный GIF становится анимированным материалом. Массив на GPU
собирается при загрузке: общий размер, mip-цепочка и расписание кадров
считаются из того, что нашлось в папке. Точная раскладка — в
[texturepacks.md](texturepacks.md).

## Звуки

Звукопак — каталог `sounds/<name>.lap` с файлами `.la` внутри. В отличие
от шейдерпака обязательного набора имён нет: имена звуков придумывает
приложение, а движок отдаёт звук по имени. Поэтому заменить любой звук —
значит положить в свой пак файл с тем же именем. Сами файлы собирает из
WAV офлайн-конвертер `laiue_soundc`. Точная раскладка — в
[soundpacks.md](soundpacks.md).

## Активный выбор

`shaders/active.txt`, `textures/active.txt` и `sounds/active.txt` содержат UTF-8-имя одного
активного пака без пути. Пустой или отсутствующий файл означает встроенный
fallback. Одиночные `.ls`, `.lt` и `.la` через `active.txt` не
выбираются: они живут внутри паков.

Рядом может лежать `formats.txt` — порядок, в котором внутри пака
ищутся форматы одного ресурса. По умолчанию исходники идут раньше
собственных `.lt` и `.la`; подробности в
[texturepacks.md](texturepacks.md).

Активация изменяет каталог, но не навязывает жизненный цикл renderer.
`RendererReloadTexturePackFrom` и `RendererReloadShaderPackFrom` выполняют
фактическую транзакционную замену из явного каталога. Звуки грузятся
поштучно через `AudioClipLoadFrom`, поэтому замены «на лету» у них нет:
приложение решает, когда перезагрузить свои клипы. Compatibility wrappers
используют каталог рядом с executable.
