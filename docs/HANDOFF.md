# Состояние передачи работы, 2026-10-04

Правила разработки находятся в CONTRIBUTING.md. Общий отчёт об измерениях
и принятых либо отклонённых оптимизациях — OPTIMIZATION_MASTER_REPORT.md.
Коммиты не содержат соавторства и служебных подписей; Git-теги не создаются.

## Текущая последовательность

Выполняются девять согласованных этапов, каждый с проверкой, отдельным
коммитом и push в main. Первый добавляет реальные сценарии `walk` для
Windows и Android: действия по фиксированным тикам, собственные GPU-кадры
Windows и удержанные ADB-снимки Android, метрики и проверку lifecycle.
Команды и ограничения — [walk_scenarios.md](walk_scenarios.md), фактические
результаты — раунд 28 общего отчёта. Проверка на эмуляторе не заменяет
физический телефон и не означает завершения качества персонажа.

Далее: общий игровой runtime; indexed geometry/instancing; суставы ragdoll;
анимации/skinning; бюджеты мира/LOD; платформенные adapters; streaming audio;
изоляция выбранных модов. Не начинать реализацию следующего этапа до
проверки предыдущего. Общий отчёт остаётся единственным местом измерений.

## Завершённые задачи

- laiue.mesh_world: разреженный бесконечный мир из моделей, координаты
  int64 + локальный float, поставщик ячеек, sweep, скольжение, луч,
  пересечения и мост к физике. В запросах по составной форме убран большой
  стековый массив, из-за которого MSVC Release с /Ob3 и LTO требовал
  отсутствующий в сборке без CRT __chkstk. Регрессия использует все 64
  коробки формы. См. [mesh_world.md](mesh_world.md).
- laiue.mesh_world_render: тест с подставным устройством проверяет
  геометрию, UV, материалы, освещение, ревизии, отсечение, rebase,
  прогрессивную сборку и бюджет буферов. Ближние ячейки вытесняют дальние;
  ошибка загрузки сохраняет прежнюю геометрию и освобождает временные
  ресурсы. Исправлены проверки контрактов и отказов памяти.
  См. [mesh_world_render.md](mesh_world_render.md).
- examples/mesh_world: модели из пака, бесконечная земля и деревья,
  движение с гравитацией, опорой, прыжком, скольжением и rebase.
  --headless 12 проверяет offscreen-графику при наличии устройства;
  без графического модуля выполняет явно обозначенную CPU-проверку.
  --frames 12 требует настоящее окно и успешные графические кадры.
  В CI добавлен оконный запуск X11 под Xvfb и lavapipe.
  См. [mesh_world_demo.md](mesh_world_demo.md).
- Потоковый WAV/MP3: ограниченная память декодера и кольцевого буфера,
  чтение файла по частям, pause/resume, seek и позиция. Файлового I/O,
  декодирования и выделений памяти в callback микшера нет. Поля сервиса
  добавлены в совместимый хвост ABI. Проверяются границы пакетов, seek,
  EOF, циклы, очереди и освобождение ресурсов. См. [audio.md](audio.md).
- laiue.animation: кодек .lk, паки .lkp, TRS, скалярные каналы,
  покадровая анимация текстур, позы скелета и CPU skinning. Есть тесты
  кодека, сэмплера и паков, фаззер и корпус входов.
  См. [animationpacks.md](animationpacks.md).
- animation и mesh_world_render включены в матрицу удаления модулей.
  Статическая проверка Android/iOS собирает все зарегистрированные CORE
  targets через whole archive, включая новые модули, без опоры на LTO.
- Предупреждения компилятора и линкера считаются ошибками; предупреждения
  не скрываются. Исправлены Windows-тесты, импортировавшие статический
  bootstrap как DLL. README и документация модулей обновлены.

## Границы текущей реализации

- Общие providers окна и ввода реализованы для Win32 и X11. Для Wayland,
  macOS, iOS и Android таких providers пока нет. Android walk использует
  отдельный адаптер NativeActivity. Переносимость CORE и успешная линковка
  не означают наличие оконного приложения на каждой платформе.
- Системный звук: WASAPI, ALSA, AAudio и CoreAudio. Отсутствие устройства
  вывода допускается; offscreen-микшер остаётся доступен.
- Потоковый звук включается явно. Для каждого системного потока используется
  отдельный worker; показатель памяти учитывает принадлежащие потоку heap
  buffers, но не резерв стека native thread, общую память устройства или
  память пользовательского источника. Точный MP3 seek прогревает декодер
  от начала: время зависит от позиции. PCM-путь сохранён.
- CPU skinning — функциональная основа, а не обещание GPU-производительности.
  Один загруженный экземпляр модуля animation обслуживает один host;
  второй одновременный экземпляр отвергается без изменения первого.
- Адаптер графики заимствует устройство и материал-текстуры. Приложение
  уничтожает адаптер до устройства. Транзакционная перестройка временно
  использует ресурсы сверх постоянного бюджета кэша.
- Демонстрация мира на моделях проверяет движение коробки. Она не заменяет
  игровой контроллер активного ragdoll и не обещает качество GTA/PEAK.

## Проверка и интеграция

Фактические результаты сборок, тестов и замеров записываются в общий отчёт.
Основная CI-матрица включает MSVC/clang-cl x64 и ARM64, Linux GCC/Clang,
ASan/UBSan, musl, ARM64, libFuzzer, Vulkan/X11, macOS x64/ARM64, а также
компиляцию и полную статическую линковку Android/iOS. Последние два профиля
не являются проверкой запуска на реальном телефоне.

При продолжении сначала проверить актуальный origin/main и его CI,
не ориентироваться на старую ветку или прежний список незавершённых задач.
Переписанная история main сохраняет деревья файлов: рабочие копии старой
истории нужно синхронизировать с новой базой.

## Практические замечания

- MSVC build и CTest (особенно laiue.install.consumer) запускаются в одной
  VS Developer shell. Не затирать её PATH после вызова VsDevCmd.bat.
- В Windows-тестах сохранять entry point из tests/test_runtime.h и
  LAIUE_STATIC=1 при статическом bootstrap. Не добавлять CRT ради stack
  probes и не отключать проверки стека.
- Форматировать изменённые строки C/H, новые файлы — целиком.
- Корпус фаззера копировать в каталог сборки: libFuzzer дописывает входы.
- Замеры выполнять без параллельных сборок, сохранять сырые повторы и
  сравнивать одинаковые профили компилятора. Для обмена скорости на память
  явно указывать процент изменения времени и границы измерения памяти.
