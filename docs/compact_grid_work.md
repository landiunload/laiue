# Компактный отбор соседей и интеграция мешера — 10 сентября 2026

## Изменения

В `rigid_body.c` координаты ячейки, ссылка цепочки и ранг тела по `stableId`
вынесены в отдельную запись размером 32 байта. При коллизии хеша narrowphase
больше не загружает большой solver cache и публичную структуру тела лишь
ради отбрасывания чужой ячейки или уже посещённой пары. Все 27 соседей,
порядок цепочек, SAT, контакты и итерации сохранены. Ранг строится после
проверки уникальности полных 64-битных ID; это не усечённый ID.

Пробуждение сначала проверяет сон и использует прежние компактные ссылки
`next`: его перенос на 32-байтные ссылки замедлял плотную кучу и не оставлен.
Дерево использует собственный путь. Дополнительный scratch — 32 байта на
тело (3,2 MB на 100 000), включая вызовы с деревом; выделений в шаге нет.
Размер и адрес статистики согласованы с `VoxelRigidBodyStepScratchBytes`.

Новые регрессии проверяют точный размер scratch и защитные области при
разном выравнивании и 1/2/3/7 телах. Другая регрессия сравнивает grid/tree
после каждого тика при движении с разворотом, увеличении/уменьшении формы,
повторном использовании слота и последующем столкновении по каждой оси.
Используются ID вплоть до `UINT64_MAX`, проверяются импульс и полное состояние.

## Замеры

Заморожены две сборки Windows clang-cl Release в каталоге игры:
`build/perf-grid-baseline-20260910` и `build/perf-grid-wake-links-20260910`.
Baseline уже содержит предыдущие оптимизации rebase, task pool, warm start,
predictive proxies и предварительное чтение 27 голов цепочек.

Чередование A/B/B/A/A/B, медиана трёх запусков каждого варианта; диагностический
`step_profile.exe`, 24 шага, равномерно разнесённые движущиеся тела над пустым
миром. Контактного решения между телами в этом сценарии почти нет.

| Сценарий | До, ms/step | После, ms/step |
| --- | ---: | ---: |
| 10 000 тел, grid | 1.9982 | 1.9377 |
| 100 000 тел, grid | 35.2160 | 28.6479 |
| 100 000 тел, tree (контроль) | 36.7624 | 36.9281 |
| Отбор пар на 100 000, grid | 20.4539 | 13.8313 |

На разреженных 100 000 телах время шага уменьшилось примерно на 18,7%,
отбора пар — на 32,4%. Контрольное дерево практически не изменилось.
Это **не** результат для плотной кучи из 100 000 тел и не прирост FPS.

Спавнер: `--ticks=3072 --threads=4 --solver=colored --profile`, порядок B/A/A/B.
Средние serial/parallel в ms: A = 5.158/2.752 и 5.262/2.838;
B = 5.264/2.778 и 5.199/3.013. Уверенного ускорения плотной сцены нет.
Замер не был полностью изолирован: в процессе замечен отдельно запущенный
mesher benchmark; в последнем B есть резкий всплеск на интервале до tick 2048.
Ни этот выброс, ни остальные результаты из среднего не удалялись.
Во всех четырёх прогонах serial/parallel совпали после всех 3072 тиков:
2400 тел, 2226 бодрствующих, 8415 контактов, 48702 кандидата.

Полный лог в игре: `build/compact-grid-final-abba-20260910.log`.
Диагностический исходник: `laiue/build/rebase-peer/proto/step_profile.c`;
штатный `laiue_physics_benchmark` также содержит разреженные и плотные сцены,
но его наполнение и длительность отличаются, поэтому цифры не смешиваются.

## Мешер и проверка

Прочитаны `mesh_step_parallel_work.md`, `mesh_followup_parallel_work.md` и
появившийся во время интеграции `mesh_transpose_parallel_work.md`. Зарегистрированы
`laiue.mesh.chunk_mesher` и отдельная цель `laiue_mesher_benchmark`; их наличие
зависит от модуля mesher, а не audio. Транспонирование и прямой выход второй
нейросети сохранены. Заявленные ей проценты ускорения не выданы за наши замеры.

После транспонирования обнаружен безусловный MSVC `__popcnt64` даже для
поддерживаемого профиля SSE2. Теперь intrinsic включается только с AVX2/AVX512,
иначе используется переносимый подсчёт битов. В SSE2 Release прошёл oracle,
в дизассемблированной DLL нет инструкции POPCNT. Запуска на старом CPU нет.

Проверки общей версии:

- Windows x64 MSVC и clang-cl, Debug/Release: движок по 29/29, игра по 6/6.
- Linux x64 GCC, Debug/Release: core по 29/29, headless-игра по 3/3.
- Linux GCC Debug ASan/UBSan, Vulkan-конфигурация: 11/11 тестов
  numeric/task/world/rigid/determinism/mesher; mesh oracle — 39 020 250 проверок.
- После защиты POPCNT mesh oracle повторён в четырёх Windows-конфигурациях
  и Linux ASan/UBSan. Для clang/GCC эта правка не меняет ветку реализации.
- Strict clang-tidy `rigid_body.c`, `rigid_body_test.c`, `rigid_broadphase_test.c`
  проходит; no-CRT imports numeric/physics/task не содержат CRT.
- Windows ARM64 clang-cl: финальная линковка physics и восьми профильных
  тестов; отдельно mesher, его oracle и benchmark в Debug/Release. Для
  no-CRT кросс-конфигурации проверка компилятора делает static try-compile:
  ARM64 CRT отсутствует; затем собираются настоящие DLL и EXE без CRT.
  Runtime ARM64, macOS, мобильные и консоли в этой итерации не проверены.

Полные логи: `build/compact-grid-{clang,msvc,linux}-matrix.log`,
`build/compact-grid-tidy.log`, `build/compact-grid-arm64-cross.log`.
Мешер: `build/compact-mesh-{arm64-cross,sse2,final-msvc,final-asan}.log`.
Ранее установленное ограничение TSAN (`unexpected memory mapping` в Docker)
не закрыто; ASan/UBSan не заменяет проверку гонок.

Открыто: производительность большой постоянно активной кучи, постоянные
manifolds и компактный активный набор. Упрощений физики ради этих цифр нет.
