# Диагностика графического устройства

`LaiueGraphicsDeviceV2` сохраняет прежний ABI V2 и получает необязательный
хвост `getDiagnostics` / `readbackFrame` / `requestFrameReadback`. Клиент проверяет `structSize`
по `LAIUE_GRAPHICS_DEVICE_V2_DIAGNOSTICS_SIZE` или
`LAIUE_GRAPHICS_DEVICE_V2_READBACK_SIZE` / `LAIUE_GRAPHICS_DEVICE_V2_READBACK_REQUEST_SIZE`,
затем сам указатель callback.
Старый поставщик без хвоста остаётся допустимым.

## Счётчики и GPU-время

`getDiagnostics` принимает caller-owned `LaiueGraphicsDiagnosticsV2`
с заполненным `structSize`. Вызов не ждёт GPU. `FRAME_VALID` означает,
что доступен последний успешно завершённый кадр. Его `frameIndex`
начинается с 1 и увеличивается только после успешного `endFrame`.
Следующая принятая попытка `beginFrame`, `resize` и неудачный
`endFrame` активного кадра снимают флаг. Ошибочный вызов с нулевым
размером или повторный `endFrame` без recording не создаёт новый кадр.

`drawCalls`, `drawnQuads`, `uploadedBytes` и `scenePasses` получены из
рендерера. `geometryPoolUsedBytes` / `geometryPoolCapacityBytes` описывают
его пул геометрии; они **не включают всю память GPU**, текстуры,
render targets, драйверные allocations и временные ресурсы.
`drawnQuads` сохраняет backend-семантику счётчика и не обозначает
универсальное число треугольников произвольного меша.

`resourceHandleCount` — число живых handle этого устройства всех типов.
`cpuShadowBytes` — сумма запрошенных размеров живых копий буферов и
шейдеров в façade. Сам объект устройства, память рендерера, временные
копии, allocator overhead и RSS сюда не входят. Это снимок при явном
опросе, а не автоматически накопленный пик потребления памяти.

`GPU_TIMING_SUPPORTED` и `GPU_TIMING_VALID` различают отсутствие
поддержки и ещё не готовый результат. Время относится к уже завершённому
backend-кадру, который может отставать от последнего отправленного.
`gpuFrameIndex` следует backend-нумерации и не сравнивается напрямую
с `frameIndex` façade. Невалидное значение нельзя записывать как нулевой
замер GPU. Отсутствующие возможности не имитируются CPU-часами.

## Чтение изображения

`READBACK_SUPPORTED` доступен у D3D12 с native window и у Vulkan с окном
или без него. Это собственное изображение рендерера, поэтому закрытое
другим приложением окно не превращает capture в снимок чужого окна.
Наличие callback само по себе не обещает поддержку у другого provider.
Захват включает уже нарисованные scene, panorama resolve и UI. Он
подтверждает собственное изображение движка, но не гарантирует, что
presentation engine действительно показал его на экране: например,
закрытое окно D3D12 может получить успешный `DXGI_STATUS_OCCLUDED`, а
Vulkan вправе отложить present при устаревшем swapchain.

Перед `beginFrame` клиент может вызвать `requestFrameReadback(device)`.
Это обязательно при `READBACK_REQUEST_REQUIRED` (D3D12). Vulkan
подтверждает запрос без дополнительной работы: его private RGBA8 color
target сохраняется отдельно от swapchain. Для D3D12 запрос включает
одну копию в собственный READBACK-буфер после сцены/UI и до Present.
Изображение остаётся доступным после успешного `endFrame`; без запроса
захват D3D12 отклоняется. Возврат 1 из запроса означает его принятие,
а не обещание успешного захвата: создание READBACK-ресурса или копия
могут не удаться. При этом обычный `endFrame` может завершиться успешно;
клиент обязательно проверяет результат самого `readbackFrame`.
Запрос D3D12 действует однократно и потребляется при записи `endFrame`.
Если `beginFrame` не смог начаться, запрос может оставаться ожидающим
до следующей успешной попытки; номер снимка проверяется отдельно.
Новый запрос D3D12 инвалидирует прежнюю диагностическую копию.

Буфер D3D12 сохраняется в рендерере для повторного чтения и следующих
явно запрошенных кадров при одинаковом размере allocation. При замене
ресурс уходит в очередь отложенного освобождения; при уничтожении
рендерер сначала ждёт GPU. Размеры строк READBACK с padding берутся
из `GetCopyableFootprints`, а приложение получает плотно упакованные
строки. Эта диагностическая память не включена в `cpuShadowBytes` или
счётчики пула геометрии; она может оставаться выделенной после capture.
`resize` между запросом и кадром отменяет запрос D3D12; `readbackFrame`
после такого кадра завершится ошибкой. Запрос во время recording запрещён.

Прямое чтение D3D12 back buffer после Present небезопасно для capture:
текущий FLIP_DISCARD не обещает сохранить его содержимое, и compositor
вправе дописать чужие окна. Смена обычного presentation mode для
диагностики не требуется. Основание: [DXGI_SWAP_EFFECT](https://learn.microsoft.com/windows/win32/api/dxgi/ne-dxgi-dxgi_swap_effect).
Vulkan возвращает private color target до swapchain blit/масштабирования
и форматной конверсии; это не чтение уже переданного presentation engine
swapchain image и не требует TRANSFER_SRC на образах swapchain.

`readbackFrame` принимает `LaiueGraphicsFrameReadbackV2`, у которого
`structSize` задан, `flags` и `reserved` равны 0, `pixels` указывает на
буфер приложения, а `capacityBytes` задаёт его доступный размер.
`expectedFrameIndex = 0` выбирает последний валидный кадр; ненулевое
значение требует точного совпадения, чтобы не принять устаревший снимок.
Буфер не должен пересекаться с дескриптором.
Хотя размер буфера задаётся `uint64_t`, текущий backend capture ограничен
`UINT32_MAX` байтами плотно упакованного изображения. Большая capacity
не расширяет этот предел. Проверяются переполнения размера/адресного
диапазона; доступность памяти по указателю остаётся обязанностью клиента.

При успехе возвращается 1, заполнены `frameIndex`, `width`, `height`,
`rowPitchBytes` и `writtenBytes`. Изображение RGBA8, строки сверху вниз,
без padding. Малый буфер отклоняется без записи пикселей, но сообщает
размеры цели. После ошибки `frameIndex` и `writtenBytes` равны 0;
undersized descriptor отклоняется без записи даже в него.

Вызов явно синхронизируется с GPU. Vulkan выделяет временный readback
буфер, D3D12 использует только явно запрошенную заранее копию. Это
диагностическая операция между кадрами. Обычный кадр без запроса не
получает staging allocations, копирование изображения или новые ожидания.
Диагностическую копию и readback нужно исключать из замеров обычного
frame latency; GPU interval D3D12 заканчивается до диагностической копии.
Поставщик не сохраняет указатель приложения и не освобождает его память.
Все вызовы устройства, включая диагностику, выполняются одним render
thread: параллельное начало кадра или resize во время capture запрещены.

Регрессионный тест `laiue.graphics.diagnostics` загружает настоящий
модуль без content provider, рисует Vulkan offscreen-треугольник и
проверяет изображение, guard bytes, повторное чтение, выбранный номер
кадра, recording/resize, размеры структур и точность CPU-счётчиков.

Оконные игровые сценарии, их запуск на Windows и Android и ограничения
проверок кадров описаны в [walk scenarios](walk_scenarios.md).
