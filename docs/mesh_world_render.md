# Отрисовка мира из моделей

`laiue.mesh_world_render` — самостоятельный модуль, работающий через
заимствованные таблицы `laiue.mesh_world` и графического устройства V2.
Он не импортирует DLL мира или конкретного графического backend-а.
Без него столкновения и потоковое наполнение мира продолжают работать.
Отключить оба модуля мира можно флагом `LAIUE_BUILD_MESH_WORLD=OFF`.

`create` принимает мир, его таблицу и устройство. Они должны жить дольше
адаптера. `registerModel` копирует геометрию, индексы и части модели;
приложение может сразу освободить исходные массивы. UV сохраняются.
`setMaterial` заимствует текстуру и sampler: адаптер освобождает только
созданные им vertex/index buffers, а не эти ресурсы приложения.

При наличии optional tails `getCapabilities`/`submitInstances` и capabilities
`NATIVE_INDICES`/`GENERIC_INSTANCES` адаптер разделяет shaded геометрию
модели между экземплярами с identity rotation, включая sign identity,
и положительным одинаковым масштабом по трём осям, если освещение точно
совпадает с запечённым. Автоматически разделяются только модели, повторённые
в двух или более ячейках с одним видимым зарегистрированным экземпляром.
Смешанные ячейки и несколько экземпляров в одной ячейке сохраняют прежнее
объединение по материалу и число элементов `draws`. Одна модель/поколение
освещения владеет общей VB/IB-парой с отдельным индексным диапазоном
каждого материала. Она используется, когда её запрошенные bytes
`24V + 4I` не превышают `24I` прежней развёрнутой копии. Это порог объёма
геометрии, без предположений о времени кадра. При бюджете меньше двух
буферов, отсутствующих callbacks/capabilities или короткой таблице
устройства сохраняется полное запекание.

Повернутые, неоднородно и отрицательно масштабированные экземпляры
собираются по ячейке и материалу. Их преобразования и солнечное/фоновое
освещение запекаются в вершины.
Изменение ревизии мира, модели или освещения вызывает пересборку;
смена привязки материала действует сразу без загрузки геометрии.
Неизменившаяся ячейка не пересоздаёт GPU-буферы. CPU-копия буфера
внутри графического устройства остаётся особенностью его реализации.

`update(camera, radius, cellBudget, &pending)` сначала собирает ближайшие
ячейки; `cellBudget=0` снимает ограничение числа пересборок за вызов.
`maximumBuffers` ограничивает общее число хранимых VB и IB (по умолчанию 1024).
Если подошедшей ячейке не хватает места, более дальние освобождаются.
Ячейка, которой даже одной не хватает бюджета, остаётся невидимой;
`overBudget` сообщает число отклонённых по бюджету пересборок.
При ошибке создания/загрузки новых буферов временные ресурсы освобождаются,
старая геометрия сохраняется и следующий `update` повторяет попытку.
Пересборка может временно требовать дополнительных слотов устройства:
новые буферы создаются до освобождения старых ради восстановления при сбое.
Общие buffers предыдущего поколения живут до замены последней ссылающейся
на них ячейки. Отказ бюджета проверяется до создания новой GPU-пары.

`draws` возвращает список относительно `renderOrigin` без перевода
абсолютных int64-координат в float. Переданный необязательный
`viewProjection` отсекает ячейки по геометрическим границам; соглашение —
row-major, `clip = position * matrix`, глубина 0..1.
`outCount` всегда сообщает полное число элементов, даже если массив
меньше списка. Для общих моделей список содержит обычный indexed draw
на каждый placement/material, с теми же buffers, origin и scale; полная
запечённая копия общей геометрии не сохраняется.

Optional tail `submit(renderer, renderOrigin, viewProjection)` объединяет
видимые placements одного поколения модели и материала в native
`submitInstances`, а запечённые ячейки передаёт обычным `submit`.
CPU scratch адаптера заранее выделяется в `update`; `submit` его не выделяет.
Provider устройства может выделять GPU-ресурсы при первом использовании.
Если после отсечения остался один placement, используется обычный indexed
`submit` без записи в кольцо инстансов. Неизменившийся `update` не повторяет
перечисление экземпляров, пересчёт политики и проверку нормалей.
Порядок кадра: `update`, device `setCamera`, device `beginFrame`, adapter
`submit`, device `endFrame`. При неудачной отправке `submit` возвращает 0;
предыдущие draw-команды в том же вызове уже могут быть записаны.
Они не откатываются; атомарность всего кадра не гарантируется.

`stats` возвращает буферы, вершины и результаты последнего
обновления/отсечения. Адаптер используется из одного потока;
`update` запрещён между `beginFrame` и `endFrame` устройства.
Поле `buffers` по-прежнему считает только VB; optional tail отдельно
сообщает `indexBuffers`, число shared `instances` и `instanceDrawCalls`
последнего `submit`. Прежний 48-byte prefix структуры stats поддерживается.

`laiue.mesh_world.render` проверяет адаптер на устройстве, которое
записывает загрузки и учитывает живые ресурсы: копирование геометрии,
материалы, свет на противоположных гранях, отсутствие повторной загрузки,
изменение ревизии/освещения, бюджет и вытеснение, сбой второй загрузки,
очистку, отсечение, int64-позиции и rebase. Отдельное
[демо](mesh_world_demo.md) использует модельные паки и реальное устройство.
