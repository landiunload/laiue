# Разработка

Перед изменением кода прочитайте [полные правила](docs/development.md):
контракты модулей и ABI, платформенные ограничения, команды сборки и CI.

Сначала запустите узкий регрессионный тест, затем сборку и полный CTest
в Debug и Release. Ошибок и предупреждений быть не должно; не скрывайте
их отключением диагностики. Дополнительно проверьте архитектуру и diff:

```powershell
pwsh -NoProfile -File tools/check_architecture.ps1
git diff --check
```

Применяйте `.clang-format` только к затронутым C/H-файлам. Для оптимизаций
нужны повторяемые замеры до и после; при изменении контракта обновляйте
ближайшую документацию.

Коммиты содержат только описание изменения, без соавторства, служебных
подписей и ссылок на сессии. Git-теги не создаются. После интеграции
проверяйте историю `main` и отсутствие локальных и удалённых тегов.
